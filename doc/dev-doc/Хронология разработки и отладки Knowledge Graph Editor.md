### v5.11.9 — `log_filtered` (аудит)

**Решение:** параметр `log_filtered=True` заполняет `self.filtered_atoms: List[Tuple[atom, reason]]`. Дедупликация по `(atom, reason)`. Zero-cost при `False`.

**Тестирование:** сравнение `log_filtered=False` vs `True` на `reg_001` — разница <5% по времени. Порог приемлем.

**Принятое правило:** каждая причина фильтрации — строка с ключевым словом (`generic_adj:`, `noise_atom:`, `attr_label node:`). Иначе вкладка «🛡️ Отфильтровано» нечитаема.

### v5.11.10 — `facts_from_questions` + корректные wh-запросы

**Проблема:** `edge('я', 'tesla', 'владеть')` в запросе к «Кто владеет Tesla?» — wh-слово заменялось fallback-субъектом.

**Решение:**
- `facts_from_questions=True` — по умолчанию факты извлекаются из всех предложений (включая вопросительные).
- В `_extract_from_doc` блок 1: `subj in _WH_LEMMAS_RU` → **не** заменяется на `FALLBACK_SUBJECT`, остаётся как есть → `extract_query` превращает в `X` → `_dedup` отфильтровывает из фактов (NPRO → generic).
- В `_dedup`: Variable-аргументы triplet не проверяются через `_is_generic_adj` (иначе spaCy EN тегирует `X` как POS X и убивает корректный query).

**Тестирование:** `qa_001` — «Кто владеет Tesla?» → `edge(X, 'tesla', 'владеть')`, `'я'` нет. Прогон QA-корпуса дал первые метрики: query 27/33.

## Период III. Разделение кнопок (v5.11.11 – v5.11.14)

### v5.11.11 — attr-label nouns

**Решение:** `ATTR_LABEL_NOUNS = {наименование, название, …, срок, дата, номер}`. `_postfilter_attr_labels` переклассифицирует:
- `edge(X, наименование, of)` → `attribute(X, наименование, 'true')` (инверсия genitive).
- `node(срок)` → отбрасывается.

**Зачем:** в НПА `наименование`/`срок` — это **ключи** атрибутов, а не сущности. Без фильтра граф заполнялся мусорными узлами.

### v5.11.12–v5.11.13 — UI-кнопки

**Принятое решение (после бага v5.9):** две независимые кнопки.

| Кнопка | `facts_from_questions` | Граф | Запросы |
|---|---|---|---|
| **📊 Факты** | `True` | пополняется | не трогается |
| **❓ Запрос** | `False` | не трогается | заполняется |

**Принцип:** не смешивать в одном хендлере. Тест `qa_001`: если нажать «📊 Факты» — граф пополняется, но поле «Запросы» пусто. Если нажать «❓ Запрос» — граф не тронут, запрос заполнен.

### v5.11.14 — безопасное редактирование

**Проблема:** при переименовании `apple → яблоко` (служебное слово) старый код:
1. `remove_node(apple)` — узел удалён, связи отброшены.
2. `add_node(яблоко)` — падает с `ValueError`.

Результат: `apple` и все связи потеряны безвозвратно.

**Решение:**
```python
try:
    g.add_node(final_id, final_type, props)   # сначала проверка
except Exception as e:
    return (*_refresh(g), f"✗ Ошибка переименования: {e}")  # граф цел
for e in g.edges: …   # перенаправление
for a in g.attributes: …
g.remove_node(old_id)  # только теперь
```

Аналогично — `h_edit_edge`.

**Тестирование:**
1. Открыть демо → клик `apple` → ID `яблоко` → 💾 → «✗ Ошибка: …служебное слово…», `apple` на месте.
2. ID `apple_inc` → 💾 → «✓ Узел обновлён», связи `apple → iphone` перенаправлены.

**Принятое правило:** любой новый хендлер возвращает `(*_refresh(g), …)` — единый контракт.

## Период IV. Q&A v2 (v5.11.15 – v5.11.17)

### v5.11.15 — грамматические фреймы

**Проблемы, выявленные на QA-корпусе:**

| Симптом | Пример | Корень |
|---|---|---|
| `edge('кто', …)` | «Кто владеет Tesla?» | wh-pronoun не заменялся на X при определённых разметках |
| `edge(X, Y, 'находиться')` вместо `находиться_в` | «Где находится?» | `-ся` guard ошибочно отключал локальный префикс |
| `edge(X, Y, _)` для possessives | «Есть ли X у Y?» | Не было явного фрейма |
| `технопарк` + `Москва` как два разных узла | «технопарк Москва» | Не было UD-склейки |
| `российский флот` → два узла | «российский флот» | Rel-adj не приводился к основе |

**Решения:**

1. **`_subj_of`: wh-pronoun root → semantic subject.**
2. **Parent-fallback для `nmod`/`appos`.**
3. **wh-locative без `-ся` guard.** `«Где находится X?»` → `edge(X, Y, 'находиться_в')`.
4. **«Есть ли X у Y?»** — явный regex-фрейм.
5. **Compound-merge UD:** NOUN + PROPN/LOC без case → `технопарк_москва`; Rel-adj + NOUN → `флот_россия`.

**Тестирование:** QA — query извлечение выросло с 27/33 до 29/33.

**Принятое правило (порядок в `_extract_from_doc`):** `compound_map` заполняется **до** основного цикла `for t in doc.tokens`. `_tok_norm` проверяет `compound_map` → `ner_id_atom` → лемматизация.

### v5.11.16 — `_dedup` и role-triple для wh

**Проблема:** `кто` в triplet-аргументе ловился `is_service_word` (NPRO → generic) → triplet отбрасывался.

**Решение:**
- `_dedup`: `if _name in _WH_LEMMAS_RU: continue`.
- В блоке 3: `role_subj_is_wh = (role_subj.lemma or '').lower() in _WH_LEMMAS_RU`.
- Дополнительно: attr/3 с Variable-аргументами очищаются.

**Тестирование:** QA — 30/33.

### v5.11.17 — position-first wh-handler

**Проблема (главная в периоде):** ранний выход `if role is None: result.append(term); continue` — Natasha иногда размечает `«кто»` не как root/nsubj → `edge('кто', …)` попадает в запрос.

**Решение:** позиционная проверка `subj == wh_lemma` / `obj == wh_lemma` выполняется **до** ветвлений по `role`.

**Тестирование:** QA — **32/33** (было 30/33). Оставшийся провал — `qa_024` (`metonymy`: «технопарк в РФ» → `технопарк_москва`) — не парсер, а KB-семантика. **Принято как известное ограничение, не регресс.**

**Итоговый baseline периода IV:** Query 32/33 = 97.0%, Answer 33/33 = 100%, Dialog 6/6 = 100%.

## Период V. Экстракция пакета (v5.12)

**Принятое архитектурное решение:**
> **Редактор графа не зависит от NL-экстрактора.** Ядро (CRUD, Prolog-импорт/экспорт, визуализация, запросы) работает без `nl2prolog`. Если пакета нет — пользователь может загрузить свой экстрактор через UI.

**Реализация:**

1. **Новый репозиторий `nl2prolog`.** Монолит `text_to_prolog.py` → пакет.
2. **Shim'ы в `kg-editor`:** `text_to_prolog.py` → `from nl2prolog import …`, `dialog.py` → `from nl2prolog.dialog import …`.
3. **Три сценария использования:** A (полный), B (без NL), C (пользовательский `.py`).

**Инциденты и исправления:**

| # | Симптом | Исправление |
|---|---|---|
| 1 | **`import kg_editor` падает без `nl2prolog`** | Двойной `try/except Exception` + флаг `_DIALOG_OK` |
| 2 | Диагностика непонятна — один флаг `_T2P_OK` смешивал «экстрактор загружен» и «пакет установлен» | Разделены `_T2P_OK`, `_NL2PROLOG_OK`, `_NL2PROLOG_VERSION`, `_DIALOG_OK` |
| 3 | «✗ text_to_prolog недоступен» без инструкций | `_extractor_hint_html()` — пошаговая инструкция |
| 4 | Аккордеон «⚙️ Пользовательский конвертер» свёрнут, хотя встроенного экстрактора нет | `open=not _T2P_OK` |
| 5 | `graph_model.py` не находил `noise.py` при отсутствии локального | 3-уровневый fallback: local → `nl2prolog.noise` → disabled |

**Тестирование трёх сценариев (обязательное перед релизом):**

```bash
# A. Полный: pip install "nl2prolog[ru,prolog]" && python -m kg_editor
#    → баннер ✅ nl2prolog X, NL-импорт работает
# B. Без NL: pip uninstall nl2prolog -y && python -c "import kg_editor"
#    → OK, баннер ℹ️ не задан, конвертер раскрыт, ядро работает
# C. Свой: UI → «⚙️ Пользовательский конвертер» → 📂 Выбрать .py → ✅ Загрузить
#    → баннер ✅ Пользовательский
```

**Все три сценария — норма.** Нарушение любого — regression, блокирует merge.

### PyVis freeze (в том же релизе)

**Проблема.** Три источника осцилляций:
- `physics.enabled: true` (без заморозки) — симуляция продолжается после stabilization;
- `edges.smooth.type: "dynamic"` — кривизна ребра пересчитывается на каждом кадре;
- `barnesHut.avoidOverlap: 0.5` — источник осцилляций на средних/больших графах.

**Решение:**
1. `_PYVIS_OPTIONS`: убран `avoidOverlap`, `smooth: continuous`, `stabilization.iterations: 300`.
2. `_PYVIS_FREEZE_JS`: заморозка physics по `stabilizationIterationsDone` + fallback по таймауту 2500 мс.
3. `waitNetwork(tries)`: защита от race condition (PyVis создаёт `window.network` асинхронно).

## Период VIII. Стабилизация диалога (v5.13.1–v5.13.2)

### v5.13.1 — `_dialog_hint_for_no_solution` fix

**Симптом.** Пользователь получает `✓ 1 решение(й)` + `💡 Решение не найдено` одновременно.

**Диагноз.** `DialogTurn.ask()` возвращает два формата:
- **Успех:** `{"solutions": [...], "query": "..."}` — ключа `"result"` **нет**.
- **Провал:** `{"result": None, "query": "..."}` — ключ есть.

`result.get("result") is None` истинно в **обоих** случаях (отсутствующий ключ `.get()` → `None`).

**Исправление:**

```python
if "result" in result and result["result"] is False:
    return hint
if "result" in result and result["result"] is None:
    return hint
if isinstance(result.get("solutions"), list) and len(result["solutions"]) == 0:
    return hint
return ""
```

**Тест:** `test_dialog_hint.py` — hint пустой при `solutions: [{X: регулятор}]`.

### v5.13.2 — possessive-фреймы в `nl2prolog`

**Симптом.** «У пользователя есть лицензия?» → `is_question: false`, факты вместо query.

**Диагноз.** Общий wh-handler не распознаёт посессивную конструкцию с предлогом «у» в начале.

**Исправление:** в `_extract_query_ru_natasha` добавлены два фрейма (после «Есть ли X у Y?»):

```python
# «У кого есть X?» → edge(X_var, obj, 'иметь') — possessive wh.
# Специфичнее — проверяем раньше.
m = re.match(r'^у\s+кого\s+есть\s+(.+)$', qlow)
if m:
    obj = self._phrase_to_atom(m.group(1))
    if obj and not self._is_noise_atom(obj):
        return [Term('triplet', [Term('иметь'), Variable('X'), Term(obj)])]

# «У X есть Y?» → edge(X, Y, 'иметь') — possessive (прямой порядок).
m = re.match(r'^у\s+(.+?)\s+есть\s+(.+)$', qlow)
if m:
    subj = self._phrase_to_atom(m.group(1))
    obj = self._phrase_to_atom(m.group(2))
    if (subj and obj
            and not self._is_noise_atom(subj)
            and not self._is_noise_atom(obj)):
        return [Term('triplet', [Term('иметь'), Term(subj), Term(obj)])]
```

**Порядок важен.** «У кого есть X?» **обязан** идти раньше «У X есть Y?». Иначе regex `^у\s+(.+?)\s+есть\s+(.+)$` захватит «кого» как subj и сломает wh.

**Тестирование:**

| Запрос | Ожидаемый query |
|---|---|
| «У пользователя есть лицензия?» | `edge('пользователь', 'лицензия', 'иметь')` |
| «У кого есть лицензия?» | `edge(X, 'лицензия', 'иметь')` |
| «Есть ли лицензия у пользователя?» | `edge('пользователь', 'лицензия', 'иметь')` (старый) |

## Период IX. Слияние графов (v5.14.0)

**Контекст.** До v5.14 редактор умел только **заменять** граф целиком (`📂 Открыть`, `🆕 Создать`, `📚 Демо`, `📥 Применить` из Prolog source). Сценарий «у меня есть два `.pl`-файла, хочу собрать общий граф» требовал ручного редактирования через `Prolog source` с риском потери данных при ошибке парсинга. В v5.14.0 добавлен аддитивный merge.

### Принятые решения

1. **Аддитивная семантика (без перезаписи).** Слияние только **добавляет** отсутствующее. Существующие узлы/рёбра/атрибуты не меняются. Это защищает текущий граф от «размытия» при merge с менее качественным файлом.
2. **Узел «выигрывает» по факту существования.** Если `apple` уже есть в графе как `org`, а в файле — как `concept`, остаётся `org`. Тип и `props` существующего узла не трогаются.
3. **Рёбра и атрибуты — дедуп по полному ключу.** Ребро — `(source, target, predicate)`, атрибут — `(entity, name, value)`. Разные значения одного атрибута сосуществуют (это разные факты, а не конфликт).
4. **`generic_filter` применяется к входящему графу.** Служебные слова, OCR-мусор и прочее, что не прошло бы `add_node`, пропускаются и учитываются как `skipped_*`. Merge не «обходит» фильтр.
5. **Ошибки по элементу не прерывают merge.** Каждый `add_*` обёрнут в `try/except`; исключение инкрементит соответствующий `skipped_*`, но цикл продолжается. Граф остаётся консистентным.
6. **`dlg_state` при merge не сбрасывается.** В отличие от `open`/`new`/`example` (полная замена → старый pending бессмыслен), merge — пополнение. Pending-вопрос остаётся валидным. Если пользователю нужен чистый диалог — он нажмёт `🗑️`.
7. **Отдельный статус-бокс `project_status` в проектной строке.** Раньше `open`/`new`/`example` писали в `import_status` внутри свёрнутого аккордеона «📥 Импорт из Prolog» — пользователь не видел результат, пока не раскроет аккордеон. Новый `project_status` виден сразу, рядом с кнопками.

### Реализация

**`graph_model.py` — два новых метода:**

| Метод | Назначение |
|---|---|
| `merge(other: KnowledgeGraph) -> Dict[str, int]` | Слить другой граф в текущий; возвращает статистику `added_nodes/edges/attributes` + `skipped_*` |
| `merge_from_prolog(text, generic_filter=None) -> Dict[str, int]` | Обёртка: `from_prolog(text)` → `merge(...)` |

Статистика возвращается словарём:
```python
{
  "added_nodes": 3, "skipped_nodes": 1,
  "added_edges": 2, "skipped_edges": 4,
  "added_attributes": 0, "skipped_attributes": 2,
}
```

**`app.py` — три изменения:**

1. **Хендлер `h_merge_file(g)`** — параллелен `h_open_file`: `_pick_file` → `merge_from_prolog` → `_refresh(g) + (status,)`.
2. **Кнопка `🔀 Объединить`** — в проектной строке, между `📂 Открыть` и `🆕 Создать`.
3. **`project_status = gr.HTML(...)`** — сразу под `stats_html`; `open`/`new`/`example`/`merge` пишут в него, а не в `import_status`.

`import_status` удалён из аккордеона «📥 Импорт из Prolog» (он и так не использовался `import_btn` — тот пишет в `src_status`).

### Инциденты и исправления

| # | Симптом | Исправление |
|---|---|---|
| 1 | Результат `open`/`new`/`example` не виден — статус уходил в свёрнутый аккордеон «📥 Импорт из Prolog» | Вынесен `project_status` в проектную строку; `import_status` удалён |
| 2 | При merge с идентичным графом пользователь видит «✓ Объединено», но ничего не изменилось | Отдельная ветка: «ℹ️ Нечего добавлять: {путь}» с указанием `skipped` |

### Тестирование

**Ручной чек-лист (обязательный перед релизом):**

1. **Пустой граф + файл** → merge эквивалентен open: все элементы добавлены, `skipped_* == 0`.
2. **Идентичный граф + тот же файл** → «ℹ️ Нечего добавлять», `added_* == 0`.
3. **Частичное пересечение** → статус `+N узлов, +M рёбер, +K атрибутов` + `пропущено: …`.
4. **Конфликт типа узла** → `apple` в графе = `org`, в файле = `concept`; после merge `apple.type == "org"`.
5. **Служебное слово в файле** → не добавляется; учитывается в `skipped_nodes`.
6. **Prolog source** → после merge обновляется автоматически (`_serialize_and_preview`).
7. **Счётчики** → `stats_html` (Узлов/Рёбер/Атрибутов) обновляются через `_refresh`.
8. **`import kg_editor` без `nl2prolog`** → по-прежнему OK (merge не импортирует `nl2prolog`).
9. **Сценарий B** → кнопка `🔀 Объединить` работает; баннер/аккордеоны не затронуты.
10. **Compound-ID** (`российская_федерация`, `тихий_океан`) → добавляются без ошибок.

## Философия хронологии: что мы оптимизировали

На протяжении всей истории проект двигался по шести осям:

1. **Точность Q&A** — от «не работало» (`edge('кто', …)`) до 97% через грамматические фреймы и position-first handler.
2. **Полнота KB building** — от мусорных узлов (`наименование`, `площадь`) до осмысленного графа через NER-blacklist + attr-labels + POS-фильтр.
3. **Устойчивость к зависимостям** — от «падает без `nl2prolog`» до трёх сценариев A/B/C.
4. **UX** — от «непонятное сообщение» до `_extractor_hint_html`, от двойных рамок до одного контура, от «диалог только в API» до полноценной вкладки, от «статус в свёрнутом аккордеоне» до `project_status` в проектной строке.
5. **Стабильность визуализации** — от «PyVis дрожит/вращается» до заморозки physics после stabilization.
6. **Композиция графов** — от «только замена целиком» до аддитивного merge без потери данных.

**Не оптимизировали намеренно:**
- Recall на OCR-фрагментах — loss принят.
- Метрики на `essay_001` — эталон некорректен.
- Скорость `log_filtered=True` — <5% overhead приемлем.
- Диалог с пользовательским `.py` — осознанное ограничение (нужен `DialogTurn` из пакета).
- **Merge с перезаписью** — не делали: аддитивность важнее для сценария «пополнить KB из внешнего источника».

## Уроки, зафиксированные в процессе

1. **«Работает в API» ≠ «работает в UI»**. `DialogTurn` существовал с v5.11.20, но в UI появился только в v5.13.0. Промежуток — 2 недели, в течение которых пользователи могли думать, что диалога нет.

2. **«Пакет работает» ≠ «интеграция работает»**. `nl2prolog.dialog.apply_facts_to_graph` вызывался успешно в тестах пакета (своя `KnowledgeGraph`), но падал в редакторе (другая `KnowledgeGraph`). Фикс — только на стороне редактора.

3. **Один симптом — несколько причин**. «Дрожит» = physics без заморозки. «Вращается» = `smooth: dynamic`. «Shimmering» = `avoidOverlap`. Один «фикс» (выключить physics) не решает всё — нужно три изменения.

4. **`.get("result") is None` — ловушка**. `dict.get` возвращает `None` для отсутствующего ключа, но `None` может быть и валидным значением. `"result" in result` — единственный надёжный способ различить.

5. **Порядок regex-фреймов критичен**. «У кого есть X?» и «У X есть Y?» — оба начинаются с `у`. Если порядок перепутан — «кого» уходит в subj, wh-handler ломается.

6. **Статус-сообщение в свёрнутом аккордеоне = статус-сообщение, которого нет**. `open`/`new`/`example` писали в `import_status` внутри «📥 Импорт из Prolog» (`open=False`). Пользователь не видел результат, пока не раскроет аккордеон. Вынос в `project_status` рядом с кнопками — очевидное решение, но заметили его только при добавлении `merge`.

7. **«Добавить ещё одну кнопку» — повод пересмотреть всю строку**. При добавлении `🔀 Объединить` обнаружилось, что `import_status` дублирует роль `src_status` (обе пишут статус импорта Prolog-кода). Удаление мёртвого `import_status` — бесплатный рефакторинг, ставший возможным из-за merge.

8. **Аддитивность — правильный default для merge**. Первая идея была «перезаписывать при конфликте». На тестовом сценарии (базовый граф + расширение с 1 конфликтом типа) выяснилось: пользователь ожидает, что его текущий граф не «размывается» менее качественным файлом. Аддитивность выбрана осознанно, `overwrite` вынесен в roadmap (P3.1).
