## 1. Ключевой UI-фикс: двойные рамки у полей ввода

### 1.1. Симптом

Каждое поле ввода (`gr.Textbox` с `elem_classes=["compact-tb"]`) отображается с **двойным контуром**: две линии `#2a313d` с тонким зазором между ними. На тёмном фоне это читается как «грязная» разметка, особенно в ряду кнопок `➕ / 💾 / 🗑️`.

### 1.2. Причина

Gradio оборачивает `<input>`/`<textarea>` в два DOM-слоя:

```
.block       ← border от темы (block_border_color="#2a313d")
  └─ <input>  ← border из нашего CSS (.compact-tb input { border: 1px solid ... })
```

Оба контура одного цвета → визуальная «двойная рамка». Ситуация усиливается тем, что `.compact-tb` стилизует **сам `<input>`**, но не снимает рамку с обёртки.

### 1.3. Решение — заменить блок в `_GLOBAL_CSS`

**Было:**

```css
.compact-tb input, .compact-tb textarea {
    padding: 3px 7px !important;
    font-size: 12px !important;
    min-height: 26px !important;
    background: #0b0d11 !important;
    color: #c7cbd1 !important;
    border: 1px solid #2a313d !important;
}
.compact-tb input:focus, .compact-tb textarea:focus {
    border-color: #58a6ff !important;
    box-shadow: 0 0 0 2px rgba(88,166,255,.2) !important;
}
```

**Стало:**

```css

 * Gradio оборачивает <input>/<textarea> в .block/.form с border от темы.
```

### 1.4. Правила, чтобы не сломать

1. **Не снимайте** глобальное `.gradio-container .block { border-color: … }` — оно нужно для аккордеонов, табов, JSON-контейнеров, `<Dropdown>` (у него нет класса `compact-tb`).
2. **Не снимайте** `.gradio-container input[type="text"] { … }` — оно работает на полях без `compact-tb` (например, в Search-панели Gradio).
3. **Специфичность важна.** `.gradio-container .compact-tb.block` (специфичность `0,3,0`) выше `.gradio-container .block` (`0,2,0`) — правило перебивает тему Gradio независимо от порядка объявления.
4. `border: none` на обёртке снимает **рамку целиком**, а не только цвет; внутренний `<input>` остаётся единственным видимым контуром.

## 2. NLP v5.11.15 → v5.11.17: что нового

> Всё, что описано в §2, относится к пакету `nl2prolog`, а не к shim `kg-editor/text_to_prolog.py`. Shim только реэкспортирует.

### 2.1. Position-first wh-handler (v5.11.17) — самая важная правка

**Проблема.** В `_extract_query_ru_natasha` был ранний выход:

```python
role = self._classify_wh_role_ru(wh_tok)
if role is None:
    result.append(term)   # ← BAIL-OUT
    continue
```

Если Natasha размечала `«кто»` не как `root`/`nsubj` (частый случай при инверсии, эллипсисе, длинных зависимостях), `role is None` → `term` возвращался как есть, и в запрос попадало `edge('кто', …)`.

**Решение.** Позиционная проверка `subj == wh_lemma` / `obj == wh_lemma` выполняется **до** ветвлений по `role`:

```python
subj_is_wh = (_name(subj) == wh_lemma
              or (wh_head_lemma and _name(subj) == wh_head_lemma))
obj_is_wh  = (_name(obj)  == wh_lemma
              or (wh_head_lemma and _name(obj)  == wh_head_lemma))

if subj_is_wh:
    result.append(Term('triplet', [pred, X, obj]))
elif obj_is_wh:
    result.append(Term('triplet', [pred, subj, X]))
elif role == 'predicate' and _name(pred) == wh_head_lemma:
    result.append(Term('triplet', [X, subj, obj]))
elif role in ('object_adverbial', 'attribute') and _name(pred) == wh_head_lemma:
    result.append(Term('triplet', [pred, subj, X]))
else:
    result.append(term)
```

`role` теперь используется **только** для `predicate` / `object_adverbial` fallback. Позиционная замена `subject ↔ X` и `object ↔ X` срабатывает безусловно.

**Проверка:**

```python
from nl2prolog import TextToProlog
t = TextToProlog()
_, q = t.parse("Кто владеет Tesla?", strict=True, facts_from_questions=False)
assert "edge(X, 'tesla'" in q  # не edge('кто', ...)
assert "'кто'" not in q
```

**Что нельзя ломать.** Если вернуть `if role is None: … continue` — регрессия qa_01, qa_02, dlg_a_t1 (см. §3).

### 2.2. Compound-merge UD (v5.11.15)

Перед `_extract_from_doc` применяются два правила склейки:

**Правило 1 — NOUN + PROPN/LOC без case:**

```
технопарк (NOUN) + Москва (PROPN, nmod без case)
  → технопарк_москва
```

Условия: `rel ∈ {nmod, appos, compound}`, у дочернего токена **нет** `rel=case`, head — NOUN. Оба токена добавляются в `compound_map`, `_tok_norm` возвращает склеенный атом.

**Правило 2 — Rel-adj + NOUN:**

```
российский (ADJ, amod) + флот (NOUN)
  → флот_россия (adj приводится к основе-существительному)
```

`_adj_to_place_stem("российский")` → `россия` (через `pymorphy3` с проверкой `tag.POS ∈ {NOUN, PROPN}`). Склеивание происходит в порядке `head_adj` (не `adj_head`).

**Проверка:**

```python
_, q = t.parse("Где находится технопарк Москва?", strict=True)
# После merge: atom = 'технопарк_москва'
assert "технопарк_москва" in q
```

**Не путать** с compound в NER (это работает всегда, §1.2 Protocol 2) — здесь другая механика: склейка по UD-дереву, а не по NER-span.

### 2.3. wh-locative без `-ся` guard (v5.11.15)

**Было.** В wh-locative блоке стоял guard: если pred оканчивался на `-ся`, префикс `в_`/`из_` не добавлялся. Логика: «возвратный глагол несовместим с локальным предлогом».

**Стало.** Guard убран.

```python
if wh_lemma in ('где', 'куда', 'откуда'):
    _prep_map = {'где': 'в', 'куда': 'в', 'откуда': 'из'}
    _suffix = _prep_map[wh_lemma]
    for _term in result:
        if _term.functor == 'triplet' and len(_term.arguments) == 3:
            _pred_atom = self._atom(_term.arguments[0])
            if '_' not in _pred_atom:   # ← единственный guard
                _new_pred = Term(f"{_pred_atom}_{_suffix}")
                ...
```

Теперь `«Где находится X?»` даёт `edge(X, Y, 'находиться_в')`, а не `edge(X, Y, 'находиться')`. Для возвратных глаголов (`«где учится?»`) также работает — `учиться_в`, что корректно.

**Проверка:**

```python
_, q = t.parse("Где находится технопарк Саратов?", strict=True)
assert "находиться_в" in q
```

### 2.4. «Есть ли X у Y?» → `edge(Y, X, 'иметь')` (v5.11.15)

Явный грамматический фрейм в `_extract_query_ru_natasha` **до** общего механизма:

```python
m = re.match(r'^есть\s+ли\s+(.+?)\s+у\s+(.+)$', qlow)
if m:
    obj  = self._phrase_to_atom(m.group(1))
    subj = self._phrase_to_atom(m.group(2))
    if obj and subj and not noise(obj) and not noise(subj):
        return [Term('triplet', ['иметь', subj, obj])]
```

Порядок: possessive → `edge(holder, property, 'иметь')`. Обратный порядок (`edge(property, holder, 'быть_у')`) не используется.

**Проверка:**

```python
_, q = t.parse("Есть ли лицензия у компании?", strict=True)
assert "edge('компания', 'лицензия', 'иметь')" in q
```

### 2.5. Role-triple для wh-subject + attr/3 cleanup (v5.11.16)

**Проблема.** В блоке 3 (`nmod + Case=Gen → of / role-triple`) wh-субъект отбрасывался фильтром:

```python
allowed = (role_subj.id not in used_ids)
if (allowed and (subj_atom not in _STOP_WORDS_RU ...)):
    ...
```

`кто` — в `_STOP_WORDS_RU` → `allowed=False` → triplet не эмитился.

**Решение.** `role_subj_is_wh` разрешает triplet даже для wh-субъекта, и дополнительно очищаются attr/3 с Variable-аргументами, которые могли остаться от предыдущих итераций:

```python
role_subj_is_wh = (role_subj.lemma or '').lower() in _WH_LEMMAS_RU
allowed = (role_subj.id not in used_ids) or role_subj_is_wh
if (allowed
        and (subj_atom not in _STOP_WORDS_RU
             or subj_atom in _WH_LEMMAS_RU)):
    conditions.append(Term('triplet', [h, subj_atom, dep]))
    ...
    conditions = [
        c for c in conditions
        if not (c.functor == 'attr' and len(c.arguments) >= 2
                and self._atom(c.arguments[0]) == dep
                and isinstance(c.arguments[-1], Variable))
    ]
```

**Что нельзя ломать.** Убрать `role_subj_is_wh` — сломать запросы вида «Кто основал компанию?» (qa_013).

### 2.6. `_dedup`: wh-слова в triplet не generic (v5.11.16)

```python
if c.functor == 'triplet' and len(c.arguments) >= 2:
    for _i in range(1, len(c.arguments)):
        _arg = c.arguments[_i]
        if isinstance(_arg, Variable):
            continue
        _name = self._atom(_arg)
        if _name in _WH_LEMMAS_RU:   # ← wh-слова пропускаются
            continue
        if self._is_generic_adj(_name):
            ...
```

Без этого `кто` ловится `is_service_word` (NPRO → generic), и triplet отбрасывается. С этим — triplet выживает.

## 4. Новые критические точки отказа (дополнение к Protocol 2 §2)

### 4.1. CSS: не снимать глобальные правила ради двойной рамки

**Симптом.** Если удалить `.gradio-container .block { border-color: … }` вместе с `.compact-tb`-фиксом — «поплывут» аккордеоны, табы, JSON-контейнеры.

**Правило.** Изменения — только через селектор `.compact-tb.block` (высокая специфичность). Глобальные правила не трогать.

### 4.2. Порт 7861

`launch()` и `main()` в `app.py` v5.12.1 используют `port=7861` по умолчанию. Если пользователь ожидает `7860` — сюрприз.

**Правило.** При изменении порта — обновить:
1. `argparse` default в `main()`.
2. `launch()` default.
3. Документацию (`README`, Protocol 3 §7).
4. `__main__.py` не зависит от порта (делегирует `app.main`).

### 4.3. `_nl_package_status_html` — 5 состояний, не 3

Если добавляете новое состояние (например, «пользовательский экстрактор, но упал при инициализации») — добавляйте ветку **в этот метод**, а не `if` в хендлерах. Иначе баннер разойдётся с реальностью.

### 4.4. `open=not _T2P_OK` — только для конвертера

Не переносите это на другие аккордеоны. У «📥 Импорт из Prolog» и «🔬 Диагностика» — фиксированное `open=False`.

### 4.5. `_extractor_hint_html` — единственный шаблон для «нет экстрактора»

Обе кнопки (`📊 Факты`, `❓ Запрос`) вызывают **один и тот же** `_extractor_hint_html()`. Не дублируйте текст в хендлерах.

### 4.6. Compound-merge order

В `_extract_from_doc` порядок обязателен:

1. `compound_map` (UD-склейка) заполняется **до** цикла `for t in doc.tokens` (поиск глаголов).
2. `_tok_norm(t)` проверяет `compound_map` **до** `ner_id_atom` **до** лемматизации.

Нарушение порядка — токены не склеятся, NER-span победит UD-склейку.

### 4.7. Port 7861 vs. share=True

`share=True` (gradio.live) игнорирует `server_port`. Это не баг, но при отладке `--share` проверять `7860`/`7861` бессмысленно.
