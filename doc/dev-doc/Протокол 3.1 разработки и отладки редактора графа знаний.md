## 1. Диалоговый режим: архитектура и точки отказа

### 1.1. Где живёт логика

| Слой | Модуль | Ответственность |
|---|---|---|
| NL-парсер | `nl2prolog.text_to_prolog` | `parse()`, possessive-фреймы, wh-handler |
| Диалог | `nl2prolog.dialog.DialogTurn` | `ask`/`answer`/`yes`/`no`/`reset`, `history`, `pending_*` |
| Применение фактов | `kg_editor.dialog.apply_facts_to_graph` | `KnowledgeGraph.from_prolog` + merge |
| UI | `kg_editor.app.h_dialog_*` | Обёртки, `_refresh`, hint |

**Правило.** Пользовательский `.py`-экстрактор (сценарий C) **не даёт** `DialogTurn` — диалог работает только с `nl2prolog`. Это осознанное ограничение.

### 1.2. Пять хендлеров

```
h_dialog_ask(g, text, t2p_cls, dlg_state)     → 6-tuple
h_dialog_answer(g, text, t2p_cls, dlg_state)  → 6-tuple
h_dialog_yes(g, t2p_cls, dlg_state)           → 6-tuple
h_dialog_no(g, t2p_cls, dlg_state)            → 6-tuple
h_dialog_reset(g, dlg_state)                  → 4-tuple
```

**6-tuple (ask/answer/yes/no):** `(graph_state, dlg_state, dlg_result, dlg_status_html, dlg_transcript_box, dialog_pending)` — плюс `.then(_refresh, [graph_state], refresh_outs)`.

**4-tuple (reset):** `(dlg_state, dlg_status_html, dlg_transcript_box, dialog_pending)` — без `.then(_refresh)` (граф не меняется).

**Правило.** Новый dialog-хендлер возвращает тот же кортеж и цепляет `.then(_refresh)`, если может изменить граф.

### 1.3. `_apply_facts_local` — обход сломанного `apply_facts_to_graph`

**Проблема.** `nl2prolog.dialog.apply_facts_to_graph` пытается `from nl2prolog import KnowledgeGraph` (которого нет) → `KnowledgeGraph = None` → `'NoneType' object has no attribute 'from_prolog'`.

**Решение в `kg_editor/dialog.py`:**

```python
from nl2prolog.dialog import DialogTurn  # noqa: F401

def apply_facts_to_graph(graph, facts_src: str):
    """Применить Prolog-факты к графу через kg_editor.KnowledgeGraph."""
    if not facts_src or not facts_src.strip():
        return graph, {"nodes": 0, "edges": 0, "attributes": 0}
    try:
        from .graph_model import KnowledgeGraph
    except ImportError:
        from graph_model import KnowledgeGraph
    try:
        new_g = KnowledgeGraph.from_prolog(facts_src)
    except Exception as e:
        return graph, {"error": str(e)}
    try:
        for n in new_g.nodes.values():
            graph.add_node(n.id, n.type, n.props)
        for e in new_g.edges:
            graph.add_edge(e.source, e.target, e.predicate)
        for a in new_g.attributes:
            graph.add_attribute(a.entity, a.name, a.value)
    except Exception as e:
        return graph, {"error": str(e)}
    return graph, {
        "nodes": len(new_g.nodes),
        "edges": len(new_g.edges),
        "attributes": len(new_g.attributes),
    }
```

**Резерв в `app.py`:** `_apply_facts_local` — копия той же логики. Используется, если shim-импорт `apply_facts_to_graph` сломан (например, установлена старая версия `kg_editor/dialog.py`).

**Правило.** Не вызывать `nl2prolog.dialog.apply_facts_to_graph` — только `kg_editor.dialog.apply_facts_to_graph` или `_apply_facts_local`.

### 1.4. `_dialog_hint_for_no_solution` — критический фикс v5.13.0

**Проблема.** `DialogTurn.ask()` возвращает **два разных формата**:

- **Успех:** `{"solutions": [...], "query": "..."}` — **ключа `"result"` нет**.
- **Провал:** `{"result": None, "query": "..."}` — ключ есть, значение `None`.

Код `result.get("result") is None` истинно в **обоих** случаях (отсутствующий ключ `.get()` → `None`). Раньше это давало ложный hint «Решение не найдено» **даже при непустых `solutions`**.

**Правило.** Проверять через `"result" in result`:

```python
if "result" in result and result["result"] is False:
    return hint
if "result" in result and result["result"] is None:
    return hint
if isinstance(result.get("solutions"), list) and len(result["solutions"]) == 0:
    return hint
return ""
```

### 1.5. Очистка pending при успешном ответе

**Проблема.** `DialogTurn.ask()` в `nl2prolog` v1.0.0–v1.0.1 оставлял `pending_query` установленным даже после успешного ответа → UI показывал «⏳ Ожидающий вопрос» → ✅/❌ пытались добавить `true_condition(edge(X, …))` с неразрешённой `X`.

**Решение (канон):** `DialogTurn.ask()` в `nl2prolog` v1.0.2 очищает `pending_*` при непустых `solutions`:

```python
if sols:
    self.pending_query = ""
    self.pending_facts = ""
    self.pending_question_text = ""
```

**Резерв в `app.py` (`h_dialog_ask`):** тот же блок — идемпотентный, безопасен, если `nl2prolog` старый. Не убирать: это защита от рассинхронизации версий.

### 1.6. Авто-сброс `dlg_state`

`dlg_state` (gr.State с `DialogTurn`) сбрасывается в `None` при:

- смене экстрактора (`t2p_load_btn`, `t2p_reset_btn`) — `.then(lambda: None, [], [dlg_state])`;
- замене графа (`open_btn`, `new_btn`, `example_btn`) — `.then(lambda: None, [], [dlg_state])`.

**Правило.** При добавлении новой кнопки, полностью заменяющей граф или экстрактор, добавлять тот же `.then`. Иначе пользователь получает pending-вопрос к старому графу.

## 2. PyVis: фикс «дрожи» и «вращения»

### 2.1. Симптом

После загрузки графа узлы «дрожат», рёбра «shimmer» — визуально «вращаются» даже без участия пользователя.

### 2.2. Три причины

| # | Ключ | Проблема |
|---|---|---|
| 1 | `physics.enabled: true` (без заморозки) | Симуляция продолжается **после** stabilization. Каждый кадр `barnesHut` пересчитывает силы → осцилляции на долях пикселя. |
| 2 | `edges.smooth.type: "dynamic"` | Кривизна ребра пересчитывается **на каждом кадре** по текущим позициям узлов. Даже при `physics: false` — shimmering. |
| 3 | `barnesHut.avoidOverlap: 0.5` | Источник осцилляций на средних/больших графах. |

### 2.3. Фикс — три изменения в `graph_layout.py`

**1. `_PYVIS_OPTIONS`** — убран `avoidOverlap`, `smooth: continuous`, `stabilization.iterations: 300`, `updateInterval: 50`, `fit: true`:

```python
_PYVIS_OPTIONS = """{
  "physics": {
    "enabled": true,
    "barnesHut": {
      "gravitationalConstant": -8000,
      "centralGravity": 0.3,
      "springLength": 180,
      "springConstant": 0.04,
      "damping": 0.09
    },
    "stabilization": {
      "enabled": true,
      "iterations": 300,
      "updateInterval": 50,
      "fit": true
    }
  },
  "edges": {
    "smooth": { "type": "continuous" },
    ...
  }
}"""
```

**2. `_PYVIS_FREEZE_JS`** — JS-хук, выключающий physics сразу после stabilization:

```python
_PYVIS_FREEZE_JS = """
<script>
(function () {
    function freeze(network) {
        var frozen = false;
        function doFreeze() {
            if (frozen) return;
            frozen = true;
            try { network.setOptions({ physics: false }); } catch (e) {}
        }
        try { network.once('stabilizationIterationsDone', doFreeze); } catch (e) {}
        setTimeout(doFreeze, 2500);   // fallback
    }
    function waitNetwork(tries) {
        tries = tries | 0;
        if (window.network && typeof window.network.setOptions === 'function') {
            freeze(window.network);
            return;
        }
        if (tries > 120) return;
        setTimeout(function () { waitNetwork(tries + 1); }, 50);
    }
    if (document.readyState === 'loading') {
        document.addEventListener('DOMContentLoaded', function () { waitNetwork(0); });
    } else { waitNetwork(0); }
})();
</script>
"""
```

**3. Инжект в `render_pyvis`** — сразу после инжекта CSS:

```python
html_content = html_content.replace(
    "</body>",
    _PYVIS_FREEZE_JS + "</body>",
)
```

### 2.4. Правила

- **Не удалять** `_PYVIS_FREEZE_JS` — без него physics продолжит работать.
- **Не возвращать** `smooth.type: "dynamic"` — это источник shimmering.
- **Не возвращать** `avoidOverlap` — осцилляции на графах 50+ узлов.
- **Таймаут 2500 мс** — fallback, если событие `stabilizationIterationsDone` не сработало (старые версии vis-network).
- **`waitNetwork`** — защита от race condition: PyVis создаёт `window.network` асинхронно.

## 3. NLP v1.0.2: possessive-фреймы

### 3.1. Новые фреймы

В `TextToProlog._extract_query_ru_natasha`, **после** «Есть ли X у Y?» (проверка порядком важна):

```python
# «У кого есть X?» → edge(X_var, obj, 'иметь') — possessive wh.
# Специфичнее общего «У X есть Y?» — проверяем раньше,
# иначе «кого» уйдёт в subj как обычный noun.
m = re.match(r'^у\s+кого\s+есть\s+(.+)$', qlow)
if m:
    obj = self._phrase_to_atom(m.group(1))
    if obj and not self._is_noise_atom(obj):
        return [Term('triplet', [Term('иметь'), Variable('X'), Term(obj)])]

# «У X есть Y?» → edge(X, Y, 'иметь') — possessive (прямой порядок).
m = re.match(r'^у\s+(.+?)\s+есть\s+(.+)$', qlow)
if m:
    subj = self._phrase_to_atom(m.group(1))
    obj = self._phrase_to_atom(m.group(2))
    if (subj and obj
            and not self._is_noise_atom(subj)
            and not self._is_noise_atom(obj)):
        return [Term('triplet', [Term('иметь'), Term(subj), Term(obj)])]
```

### 3.2. Порядок фреймов

```
Что такое X?           → node(X, [], T)
Сколько X в Y?          → attribute(Y, количество_X, V)
Какие X есть в Y?       → edge(X, Y, 'находиться_в')
Когда <participle> X?   → attribute(X, год_<...>, V)
Есть ли X у Y?          → edge(Y, X, 'иметь')
У кого есть X?          → edge(X_var, X, 'иметь')   ← специфичнее
У X есть Y?             → edge(X, Y, 'иметь')
--- общий wh-handler ---
```

**Правило.** «У кого есть X?» **обязан** идти раньше «У X есть Y?». Иначе regex `^у\s+(.+?)\s+есть\s+(.+)$` захватит «кого» как subj и сломает wh.

### 3.3. Тесты

| Запрос | Ожидаемый query |
|---|---|
| «У пользователя есть лицензия?» | `edge('пользователь', 'лицензия', 'иметь')` |
| «У кого есть лицензия?» | `edge(X, 'лицензия', 'иметь')` |
| «Есть ли лицензия у пользователя?» | `edge('пользователь', 'лицензия', 'иметь')` (старый фрейм) |

**Известное ограничение.** Если KB содержит `edge('пользователь', 'лицензия', 'имеет')` (не лемматизированный предикат), запрос с `'иметь'` не найдёт решений. Это вопрос нормализации предикатов в KB, не парсера.

## 4. Транскрипт `DialogTurn.transcript()`

### 4.1. Что печатает (v1.0.2)

```
[01] user/question
     «Кто выдает лицензию?»
     Q: edge(X, 'лицензия', 'выдавать')

[02] system/answer
     Q: edge(X, 'лицензия', 'выдавать')
     ✓ 1 решение(й):
         X=регулятор
```

### 4.2. Что печаталось раньше (v1.0.0–v1.0.1)

```
[user/question] Кто выдает лицензию?
    Q: edge(X, 'лицензия', 'выдавать')
[system/answer]
    Q: edge(X, 'лицензия', 'выдавать')
```

Пустой `text` у `system/answer` (нет ключа) + отсутствие `solutions` — транскрипт неинформативен.

### 4.3. Правило

**Не реализовывать** рендер транскрипта в `app.py` (`_dialog_transcript_str` должен быть тонкой обёрткой над `dlg_state.transcript()`) — иначе дублирование форматов. Если нужен новый формат — править `nl2prolog.dialog.transcript()`.

```python
def _dialog_transcript_str(dlg_state) -> str:
    if dlg_state is None:
        return "(диалог не начат)"
    try:
        t = dlg_state.transcript(n=20)
        return t if t else "(пусто)"
    except Exception:
        return "(ошибка чтения транскрипта)"
```

## 5. Критические точки отказа (дополнение к Protocol 3.0 §4)

### 5.1. `_apply_facts_local` — обязателен

Если `kg_editor/dialog.py` старый или `nl2prolog.dialog.apply_facts_to_graph` вызывается напрямую — `'NoneType' object has no attribute 'from_prolog'`.

**Правило.** Импорт `apply_facts_to_graph` — только из `kg_editor.dialog`. Резервный вызов — через `_apply_facts_local` в `app.py`. Не вызывать `nl2prolog.dialog.apply_facts_to_graph`.

### 5.2. `_dialog_hint_for_no_solution` — только `"result" in result`

`result.get("result") is None` даёт ложный hint при успешном ответе (ключа `"result"` нет в success-формате).

**Правило.** Всегда проверять `"result" in result` **перед** `.get()`. Покрыть тестом:

```python
def test_hint_on_success():
    assert _dialog_hint_for_no_solution(
        {"solutions": [{"X": "регулятор"}], "query": "..."},
        dlg_with_pending
    ) == ""
```

### 5.3. Pending-cleanup — в `DialogTurn.ask()`, а не в `app.py`

**Канон:** `nl2prolog.dialog.DialogTurn.ask()` очищает `pending_*` при непустых `solutions`. Резерв в `h_dialog_ask` — идемпотентный, но **не** должен быть единственным.

**Правило.** Если правите `h_dialog_ask` — не удаляйте резервный блок. Если правите `DialogTurn.ask` — оставляйте очистку.

### 5.4. `dlg_state` сбрасывается при смене контекста

Любая кнопка, заменяющая граф (📂/🆕/📚) или экстрактор (📂/✅/↺), должна цеплять `.then(lambda: None, [], [dlg_state])`.

**Правило.** При добавлении новой такой кнопки — проверить, что `dlg_state` не тянет pending из прошлой сессии.

### 5.5. `_PYVIS_FREEZE_JS` и `smooth: continuous` — не откатывать

См. §2.4. Это единственный способ убрать «дрожь» без полного отключения physics (что убивает красивую стабилизацию).

### 5.6. Порт 7861

`launch()` и `main()` в `app.py` v5.13 используют `port=7861` по умолчанию.

**Правило.** При изменении порта — обновить:
1. `argparse` default в `main()`.
2. `launch()` default.
3. Документацию (README, Protocol 3.1 §7).
4. `__main__.py` не зависит от порта (делегирует `app.main`).

`--share` игнорирует `server_port` — это не баг, при отладке проверять `7861` бессмысленно.

К списку Protocol 3.0 §6 добавляются:

- ❌ **Забывать** `.then(lambda: None, [], [dlg_state])` при добавлении кнопки, заменяющей граф или экстрактор.
- ❌ **Возвращать** `smooth.type: "dynamic"` — источник shimmering.
- ❌ **Возвращать** `barnesHut.avoidOverlap` — источник осцилляций.
- ❌ **Удалять** `_PYVIS_FREEZE_JS` — physics продолжит работать, граф «дрожит».

- ❌ **Полагать**, что `DialogTurn.ask()` не оставит pending при успехе — это ответственность пакета (v1.0.2), а резерв в `h_dialog_ask` — защита от старых версий.
