## 0. Общее описание проекта

**Knowledge Graph Editor** — веб-приложение на Gradio для создания, редактирования и визуализации графов знаний в формате Prolog-фактов (`node/3`, `edge/3`, `attribute/3`). Запросы — через **PyAgentProlog**. NL-импорт — через **пакет `nl2prolog`** (опционально) или пользовательский `.py`-модуль.

**Ключевой архитектурный принцип (v2.0):**  
> **Редактор графа не зависит от NL-экстрактора.** Ядро (CRUD, Prolog-импорт/экспорт, визуализация, запросы) работает без `nl2prolog`. Если пакета нет — пользователь может загрузить свой экстрактор через UI. Это позволяет использовать редактор как самостоятельный инструмент.

**Основной стек:**
- Python 3.10+
- Gradio 4.x / 5.x / 6.x
- PyVis (визуализация) — опционально
- PyAgentProlog (запросы) — опционально
- `nl2prolog` (NL-импорт) — **опционально**, экстрактор по умолчанию

## 2. Критические точки отказа (расширено в v2.0)

### 2.1. Импорт `dialog.py` при отсутствии `nl2prolog` ⚠️ **НОВОЕ**

**Проблема (v5.11.14):** shim `kg-editor/dialog.py` делает `from nl2prolog.dialog import …`. Если пакета нет:
- `app.py` пробует `from .dialog import …` → падает
- `except ImportError` пробует `from dialog import …` → тот же shim → падает снова
- `__init__.py` тоже не обёрнут → **`import kg_editor` падает полностью**, редактор не стартует

**Решение (v5.12):** двойной `try/except Exception` с флагом `_DIALOG_OK`:

```python
try:
    try:
        from .dialog import DialogTurn, apply_facts_to_graph
    except ImportError:
        from dialog import DialogTurn, apply_facts_to_graph
    _DIALOG_OK = True
except Exception:
    DialogTurn = None
    apply_facts_to_graph = None
    _DIALOG_OK = False
```

`DialogTurn` в UI не используется (хендлеры — заглушки), но импорт должен быть безопасным.

**Проверка:** `pip uninstall nl2prolog && python -c "import kg_editor"` — должно быть `OK`.

### 2.2. Три флага состояния в `app.py` ⚠️ **НОВОЕ**

`app.py` определяет три независимых флага:

| Флаг | Что означает | Где проверять |
|---|---|---|
| `_T2P_OK` | загружается ли `text_to_prolog` (shim или локальный) | NL-импорт |
| `_NL2PROLOG_OK` | установлен ли пакет `nl2prolog` | баннер статуса |
| `_AGENT_OK` | доступен ли `PyAgentProlog` | панель запросов |
| `_DIALOG_OK` | загружается ли `dialog` | диагностика |

**Не путать:** `_T2P_OK` и `_NL2PROLOG_OK` независимы. Возможна комбинация `_NL2PROLOG_OK=True, _T2P_OK=False` (shim сломан) — это отдельный сценарий баннера.

### 2.3. Баннер статуса экстрактора ⚠️ **НОВОЕ**

**Функция** `_nl_package_status_html(t2p_custom=False)` возвращает 5 вариантов HTML:

| Условие | Баннер | Что делать пользователю |
|---|---|---|
| `t2p_custom=True` | ✅ Пользовательский экстрактор | ничего |
| `_T2P_OK and _NL2PROLOG_OK` | ✅ nl2prolog X — по умолчанию | ничего |
| `_NL2PROLOG_OK and not _T2P_OK` | ⚠️ nl2prolog есть, shim сломан | переустановить или загрузить `.py` |
| `_T2P_OK and not _NL2PROLOG_OK` | ✅ Встроенный (локальный) | ничего (нестандартная сборка) |
| ни то, ни другое | ℹ️ Не задан + инструкция | загрузить `.py` или `pip install` |

**Правило:** любое новое состояние (новый экстрактор, новая ошибка) — добавлять строку в этот метод, а не раскидывать `if` по хендлерам.

### 2.4. `open=not _T2P_OK` для конвертера ⚠️ **НОВОЕ**

Аккордеон «⚙️ Пользовательский конвертер» должен быть **раскрыт по умолчанию, если встроенного экстрактора нет**:

```python
with gr.Accordion(
    "⚙️ Пользовательский конвертер",
    open=not _T2P_OK,  # ← важно
):
```

Иначе пользователь видит «Экстрактор не задан» и не понимает, куда нажимать.

### 2.5. Понятные сообщения в хендлерах NL-импорта ⚠️ **НОВОЕ**

`h_import_full_graph` и `h_extract_query` при `cls is None` **не** должны возвращать «✗ text_to_prolog недоступен» (непонятно). Они должны вызывать `_extractor_hint_html()`:

```
ℹ️ Экстрактор NL не задан.

Редактор графа работает полностью — можно открывать/сохранять .pl,
редактировать узлы/рёбра/атрибуты, импортировать Prolog-код,
строить запросы.

Для NL-импорта нужно:
  → Загрузить свой .py-модуль с классом TextToProlog
  → Или установить встроенный: pip install "nl2prolog[ru]"
```

**Правило:** каждое сообщение об ошибке должно содержать **что делать дальше**.

### 2.6. `graph_model.py` — fallback на `nl2prolog.noise` ⚠️ **НОВОЕ**

Раньше `graph_model.py` искал `noise.py` только локально. Если его нет — фильтрация отключалась. В v5.12 добавлен третий уровень:

```python
try:
    from .noise import is_service_word
except ImportError:
    try:
        from noise import is_service_word
    except ImportError:
        try:
            from nl2prolog.noise import is_service_word
        except ImportError:
            is_service_word = None
```

**Правило:** если `_is_service_word is None`, `_default_generic_filter` возвращает `False` (разрешает всё), а не падает. Compound-ID (`российская_федерация`) по-прежнему пропускаются (проверка `'_' in w` до вызова `is_service_word`).

### 2.7. Gradio 6.0 migration

**Проблема:** в Gradio 6.0 `theme`, `css`, `head` перенесены из `gr.Blocks()` в `ui.launch()`.

**Решение:** флаг `_LAUNCH_THEME = _GRADIO_VERSION >= (6, 0)`. Условная передача в `build_ui()` и `launch()`.

**Правило:** любая новая опция Gradio (например, `favicon_path`, `pwa`) — тоже через `_LAUNCH_THEME`.

### 2.8. PyVis: iframe и высота 100%

**Проблема:** PyVis рендерится в `<iframe srcdoc="...">`. Без явной высоты — canvas сжимается в 0px.

**Решение:** в `graph_layout.py` инжектится `_PYVIS_INJECT`:

```css
html, body, .card, .card-body, #mynetwork { height: 100% !important; }
```

**Никогда не удаляйте этот блок.** Он длинный, но каждая строчка — рабочий обход бага PyVis.

### 2.9. NLP: `RecursionError` в `_subj_of` (обновлено в v2.0) ⚠️

**Проблема 1 (visited):** Natasha/SpaCy могут создать цикл в дереве зависимостей. В `_subj_of` передаётся `visited` set — если токен уже посещён, рекурсия прерывается.

```python
if verb_tok.id in visited:
    return None
visited.add(verb_tok.id)
```

**Никогда не удаляйте эту проверку.** Даже если кажется, что «Natasha не создаёт циклов» — на длинных нормативных текстах создаёт.

**Проблема 2 (self-loop) — НОВОЕ:** Natasha иногда ставит `rel=amod head=self` на preverbal NOUN. Например, «В какой стране находится технопарк Саратов?» → `технопарк` получает `head=self`, `находится` не находит `nsubj` → fallback `'я'` или `''`.

**Решение (v5.11.19+):** fallback в `_subj_of` для `verb_tok.rel == 'root'`:

```python
if verb_tok.rel == 'root':
    # backward loop — канонический SVO
    # forward loop  — VS-инверсия (qa_026)
```

**Оба цикла обязательны.** Убрать forward — сломать qa_026. Убрать backward — сломать «Кто директор?».

**Проверка:**

```python
from nl2prolog import TextToProlog
t = TextToProlog()
_, q = t.parse("В какой стране находится технопарк Саратов?",
               strict=True, facts_from_questions=False)
assert "'технопарк_саратов'" in q  # не 'я', не ''
```

### 2.10. NLP: `strict` propagation (обновлено в v2.0) ⚠️

**Проблема (исправлено в v5.11.19):** `parse(strict=True)` **не** пробрасывал `strict` в `extract_query`, поэтому в Q&A-режиме fallback `'я'` всё равно применялся.

**Решение:** цепочка проброса обязательна на трёх уровнях:

```
parse(strict)
    → extract_query(sent, strict=strict)
        → _extract_query_ru_natasha(text, strict=strict)
            → _extract_conditions_ru_natasha(text, doc=doc, strict=strict)
                → _extract_from_doc(doc, strict=strict)
```

**Правило:** если добавляете новый публичный метод, принимающий `strict`, — пробрасывайте его до `_extract_from_doc`. Это не «уже работает» — это **явная цепочка**.

### 2.11. NLP: `facts_from_questions` (обновлено в v2.0) ⚠️

**Проблема:** в Q&A-режиме факты из вопроса попадают в граф (`«Кто владеет Tesla?»` → `node(tesla)` не нужен в KB).

**Решение:** параметр `facts_from_questions=False` — факты только из декларативов, запросы только из вопросов.

**Правило:** в UI это разделено на две кнопки:

| Кнопка | `facts_from_questions` | Граф | Запросы |
|---|---|---|---|
| **📊 Факты** | `True` | пополняется | не трогается |
| **❓ Запрос** | `False` | не трогается | заполняется |

Не смешивайте в одном хендлере — это баг v5.9, исправлен в v5.10.

### 2.12. Безопасное редактирование узлов

**Проблема:** при переименовании `российская_федерация → рф` старый код удалял узел, потом пытался создать новый. Если новый ID не проходил валидацию → узел терялся.

**Решение (сохранено):** сначала `add_node`, потом перенаправление связей, только затем `remove_node`.

```python
try:
    g.add_node(final_id, final_type, props)   # проверка валидности
except Exception as e:
    return (*_refresh(g), f"✗ Ошибка переименования: {e}")  # граф цел

for e in g.edges: …  # перенаправление
for a in g.attributes: …
g.remove_node(old_id)  # только теперь
```

Аналогично — `h_edit_edge`.

### 2.13. UI: цветные таблицы и клики

**Проблема:** `gr.Dataframe` не поддерживает HTML; `gr.HTML` не кликается.

**Решение:** `gr.Dataframe(datatype=["str", "html", "str"], …)` — HTML в ячейках, клики через `.select()` → индекс строки → подстановка в текстовые поля.

**Правило:** при добавлении колонки в `_nodes_data` / `_edges_data` не забыть добавить `"html"` в `datatype`. Иначе увидите `&lt;span&gt;...`.

### 2.14. UI: кнопки в один ряд

**Проблема:** Gradio переносит кнопки при нехватке места.

**Решение:** `elem_classes=["nowrap-row"]` + `scale=1`/`scale=0` + `min_width=0`.

**Правило:** не полагайтесь на `gr.Row(equal_height=True)` — только `nowrap-row` даёт жёсткий ряд.

### 2.15. Компаунд-ID (compound-ID)

**Проблема (исправлено в v5.11):** `российская_федерация`, `northern_ireland` падали с «служебное слово».

**Решение:** `_default_generic_filter` пропускает атомы с `_` **до** вызова `is_service_word`:

```python
if '_' in w:
    return False
```

**Правило:** любая новая проверка служебных слов в `graph_model.py` должна начинаться с этой проверки.

## 3. Правила безопасной разработки (обновлено в v2.0)

### 3.1. Сначала модель, потом UI
Новое свойство узла (например, `description`) → сначала `graph_model.py` (`add_node`, `to_prolog`, `from_prolog`), потом `gr.Dataframe` в `app.py`.

### 3.2. Пакет `nl2prolog` — отдельно от `kg-editor`
- Логика NL — **только** в `nl2prolog`.
- В `kg-editor` — **только shim'ы** (`text_to_prolog.py`, `dialog.py`) и пользовательский `noise.py` (опционально).
- Изменения в парсере → PR в `nl2prolog`, не в `kg-editor`.
- Изменения в UI-хендлерах → PR в `kg-editor`.

### 3.3. Никогда не делайте `nl2prolog` обязательным
Любой `import nl2prolog` в `app.py` / `graph_model.py` должен быть в `try/except`. Проверка:

```bash
pip uninstall nl2prolog -y
python -c "import kg_editor"  # должно быть OK
```

Если падает — regression, блокирует merge.

### 3.4. Три сценария тестирования (A, B, C)

Перед каждым релизом — проверить все три:

| Сценарий | Команда | Ожидание |
|---|---|---|
| **A. Полный** | `pip install "nl2prolog[ru,prolog]" && python -m kg_editor` | Баннер ✅ nl2prolog, NL-импорт работает |
| **B. Без NL** | `pip uninstall nl2prolog -y && python -m kg_editor` | Баннер ℹ️ не задан, конвертер раскрыт, ядро работает |
| **C. Свой** | загрузить `.py` через UI | Баннер ✅ Пользовательский |

### 3.5. Никогда не ломайте `from_prolog` / `to_prolog`
Это контракт с PyAgentProlog. Если меняете формат — старые `.pl` должны читаться. Тест:

```bash
python -c "
from kg_editor import KnowledgeGraph
g = KnowledgeGraph.from_prolog('node(a, [], concept). edge(a, b, r).')
assert g.summary() == {'nodes': 2, 'edges': 1, 'attributes': 0}
"
```

### 3.6. Изоляция состояния
Все изменения — в `graph_state` (`gr.State(KnowledgeGraph())`). UI **не** мутирует объекты напрямую — только через хендлеры, возвращающие `_refresh(g)`.

**Правило:** новый хендлер возвращает кортеж `(*_refresh(g), …)` — это единый контракт.

### 3.7. Тестируйте граничные случаи
- Пустой граф.
- Узлы со спецсимволами (`тихий_океан`, `x_1`).
- Очень длинные тексты (проверка на рекурсию в `_subj_of`).
- Попытка создать узел с ID, который уже существует.
- Отсутствие `nl2prolog` (сценарий B).
- Отсутствие `PyAgentProlog` (панель запросов должна показать заглушку).

### 3.8. Понятные сообщения — часть контракта
Каждое сообщение об ошибке содержит **действие**: «обновите X», «установите Y», «загрузите .py». См. §2.5.

### 3.9. Один флаг — один сценарий
Не плодите флаги. Сейчас их 4 (`_T2P_OK`, `_NL2PROLOG_OK`, `_AGENT_OK`, `_DIALOG_OK`). Новый — только если новая независимая зависимость.

## 4. NL-экстрактор: три режима и их контракт

### 4.1. Контракт пользовательского `.py`

```python
class TextToProlog:
    def __init__(self, **kwargs): ...
    def parse(self, text, **kwargs) -> tuple[str, str]: ...
    # или
    def convert(self, text, mode="graph", **kwargs) -> str: ...

    # опционально
    filtered_atoms: list[tuple[str, str]] = []
```

Проверки в `h_load_t2p_module`:
1. Файл существует, `.py`.
2. Импортируется без ошибок.
3. Класс `TextToProlog` присутствует.
4. Есть `parse` или `convert`.
5. Инициализируется без аргументов.

Если любой шаг провалился — сообщение с указанием, какой именно.

### 4.2. Контракт `parse()`

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `strict` | `False` | не подставлять `'я'` вместо субъекта |
| `facts_from_questions` | `True` | извлекать факты и из вопросов |
| `log_filtered` | `False` | заполнить `filtered_atoms` |
| `link_components` | `False` | добавить `alias/2` для UI |
| `lang` | `"auto"` | `"ru"` / `"en"` / авто |

**Правило:** если добавляете параметр — с `default`, чтобы старые вызовы работали.

### 4.3. Контракт `filtered_atoms`

```python
[(term_desc: str, reason: str), …]
```

Применяется только при `log_filtered=True`. Хендлер `h_import_full_graph` читает `t2p.filtered_atoms` и передаёт на вкладку «🛡️ Отфильтровано».

### 4.4. Краткая карта возможностей `nl2prolog` v1.0.0

**Грамматические фреймы** (общие для всех доменов):

| NL | Query |
|---|---|
| «Что такое X?» | `node(X, [], T)` |
| «Сколько X в Y?» | `attribute(Y, количество_X, V)` |
| «Когда \<participle\> X?» | `attribute(X, год_\<verbal_noun_gen\>, V)` |
| «Есть ли X у Y?» | `edge(Y, X, 'иметь')` |
| «Какие X есть в Y?» | `edge(X, Y, 'находиться_в')` |

**QA-метрики эталона (33 пары + 2 диалога):**

| Метрика | Значение |
|---|---|
| Query extraction | 32/33 = 97.0% |
| Answer accuracy | 33/33 = 100% |
| Dialog turns | 6/6 = 100% |

### 5.4. Проверка `_subj_of` (forward-loop)

```python
from nl2prolog import TextToProlog
t = TextToProlog()
for q in [
    "В какой стране находится технопарк Казань?",
    "В какой стране находится технопарк Саратов?",   # ← self-loop
    "В какой стране находится технопарк Москва?",
]:
    _, query = t.parse(q, strict=True, facts_from_questions=False)
    print(f"{q!r:50} → {query!r}")
# Все три должны дать edge('технопарк_X', X, 'находиться_в')
```

**Правило:** каждая причина фильтрации в `_log_filtered` должна быть **строкой с ключевым словом** (`generic_adj:`, `noise_atom:`, `compound_ner_blacklisted:`). Это делает вкладку читаемой.
