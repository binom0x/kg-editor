# 📜 Протокол разработки и отладки: Knowledge Graph Editor

## 1. Общее описание проекта
**Knowledge Graph Editor** — это веб-приложение на базе Gradio для создания, редактирования и визуализации графов знаний. Граф хранится в формате Prolog-фактов (`node/3`, `edge/3`, `attribute/3`), а запросы к нему выполняются через движок **PyAgentProlog**.

**Основной стек:**
*   Python 3.10+
*   Gradio (4.x, 5.x, 6.x)
*   PyVis (для интерактивной визуализации)
*   PyAgentProlog (движок запросов)
*   Natasha / SpaCy (NLP для извлечения фактов из текста)

## 2. Структура файлов
*   `app.py` — Интерфейс (Gradio Blocks), обработчики событий, CSS, темы.
*   `graph_model.py` — Модель данных (`KnowledgeGraph`), CRUD-операции, парсинг и сериализация Prolog.
*   `graph_layout.py` — Генерация HTML/SVG для PyVis (визуализация графа).
*   `text_to_prolog.py` — NLP-модуль (преобразование текста в Prolog-факты и запросы).
*   `dialog.py` — (Опционально) Логика ведения диалога Q&A.

## 3. Критические точки отказа (Known Issues & Fixes)

При доработке кода обращайте внимание на следующие места, которые уже вызывали ошибки:

### 3.1. Gradio 6.0 Migration
**Проблема:** В Gradio 6.0 параметры `theme`, `css` и `head` были перенесены из `gr.Blocks()` в `ui.launch()`.
**Решение:** В `app.py` есть флаг `_LAUNCH_THEME`. Убедитесь, что при инициализации UI и запуске `launch()` параметры передаются условно, в зависимости от версии Gradio.

### 3.2. PyVis: iframe и высота 100%
**Проблема:** PyVis рендерится внутри `<iframe srcdoc="...">`. Если родительский контейнер не имеет жестко заданной высоты, canvas графа сжимается в 0px.
**Решение:** В `graph_layout.py` в `_PYVIS_INJECT` инжектируется CSS: `html, body, .card, .card-body, #mynetwork { height: 100% !important; }`. Не удаляйте эти стили.

### 3.3. NLP: RecursionError в `_subj_of`
**Проблема:** В `text_to_prolog.py` при разборе длинных предложений Natasha/SpaCy могут создавать циклические ссылки в дереве зависимостей.
**Решение:** В функции `_subj_of` (внутри `_extract_from_doc`) передается множество `visited`. Если токен уже посещен, рекурсия прерывается. **Никогда не удаляйте проверку `if verb_tok.id in visited`**.

### 3.4. Безопасное редактирование узлов (Потеря данных)
**Проблема:** При переименовании узла (например, `российская_федерация` → `рф`) старый код сначала удалял узел, затем пытался создать новый. Если новый ID не проходил валидацию (являлся служебным словом), узел терялся вместе со всеми связями.
**Решение:** В функции `h_edit_node` (`app.py`) сначала вызывается `g.add_node(final_id, ...)`. Если он отрабатывает без ошибок, тогда связи перенаправляются, и только потом вызывается `g.remove_node(old_id)`.

### 3.5. UI: Цветные таблицы и клики (Dataframe)
**Проблема:** Обычный `gr.Dataframe` не поддерживает HTML-теги, а клики по строкам `gr.HTML` не отслеживаются.
**Решение:** Используется `gr.Dataframe(datatype=["str", "html", "str"], ...)`. В ячейки передается HTML-код с цветными бейджами. Клик по строке обрабатывается через событие `.select()`, которое возвращает индекс строки. Данные из этой строки подставляются в текстовые поля.

### 3.6. UI: Кнопки в один ряд
**Проблема:** Gradio по умолчанию переносит кнопки на новую строку, если не хватает места.
**Решение:** Используется CSS-класс `.nowrap-row` (`flex-wrap: nowrap !important;`). Для кнопок задан `scale=1` или `scale=0` и `min_width=0`.

## 4. Правила безопасной разработки (Workflow)

Если вы просите ИИ внести изменения, придерживайтесь следующих шагов:

1.  **Сначала модель, потом UI.** Если нужно добавить новое свойство узла (например, `description`), начните с `graph_model.py` (методы `add_node`, `to_prolog`, `from_prolog`), затем добавьте колонку в `gr.Dataframe` в `app.py`.
2.  **Тестируйте граничные случаи.**
    *   Пустой граф.
    *   Узлы со спецсимволами.
    *   Очень длинные тексты (проверка на рекурсию).
    *   Попытка создать узел с ID, который уже существует.
3.  **Никогда не ломайте `from_prolog` / `to_prolog`.** Это основной контракт с PyAgentProlog. Если меняете формат, убедитесь, что старые `.pl` файлы всё ещё читаются.
4.  **Изоляция состояния.** Все изменения графа происходят в `graph_state` (объект `gr.State(KnowledgeGraph())`). UI не должен изменять объекты напрямую — только через хендлеры (`h_add_node`, `h_edit_edge` и т.д.), которые возвращают кортеж `_refresh(g)`.

## 5. Инструкция для запуска и проверки

1.  **Запуск:** `kg-editor` (если установлен как пакет) или `python app.py`.
2.  **Проверка NLP:** Вставить текст «Илон Маск владеет SpaceX» → нажать «📊 Факты» → убедиться, что создались узлы и рёбра.
3.  **Проверка редактирования:** Кликнуть по узлу в таблице → изменить ID → нажать 💾. Проверить, что связи (если они были) не отвалились.
4.  **Проверка запросов:** Ввести `edge(X, Y, owns).` → нажать «▶ Запрос» → должен вернуться JSON с решением.
5.  **Проверка визуализации:** Нажать `⛶` на PyVis-графе — он должен развернуться на весь экран.
