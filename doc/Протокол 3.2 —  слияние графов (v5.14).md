## 11. Слияние графов (v5.14)

### 11.1. Контекст и принятые решения

**Контекст.** До v5.14 редактор умел только **заменять** граф целиком (`📂 Открыть`, `🆕 Создать`, `📚 Демо`, `📥 Применить` из Prolog source). Сценарий «есть два `.pl`-файла, нужен общий граф» требовал ручного редактирования через `Prolog source` с риском потери данных при ошибке парсинга.

**Принятые решения:**

1. **Аддитивная семантика (без перезаписи).** Слияние только **добавляет** отсутствующее. Существующие узлы/рёбра/атрибуты не меняются — текущий граф не «размывается» менее качественным файлом.
2. **Узел «выигрывает» по факту существования.** Если `apple` уже есть как `org`, а в файле — как `concept`, остаётся `org`. Тип и `props` существующего узла не трогаются.
3. **Дедуп по полному ключу.** Ребро — `(source, target, predicate)`, атрибут — `(entity, name, value)`. Разные `value` одного атрибута сосуществуют (это разные факты, а не конфликт).
4. **`generic_filter` применяется к входящему.** Служебные слова, OCR-мусор и прочее, что не прошло бы `add_node`, пропускаются и учитываются как `skipped_*`. Merge не «обходит» фильтр.
5. **Ошибка по элементу не прерывает merge.** Каждый `add_*` в `try/except`; исключение инкрементит `skipped_*`, цикл продолжается. Граф остаётся консистентным.
6. **`dlg_state` при merge не сбрасывается.** В отличие от `open`/`new`/`example` (полная замена → pending бессмыслен), merge — пополнение. Pending-вопрос остаётся валидным. Если нужен чистый диалог — `🗑️` на вкладке «💬 Диалог».
7. **Отдельный `project_status` в проектной строке.** Раньше `open`/`new`/`example` писали в `import_status` внутри свёрнутого аккордеона «📥 Импорт из Prolog» — пользователь не видел результат. Новый `project_status` виден сразу.

### 11.2. API `graph_model.py`

```python
class KnowledgeGraph:
    def merge(self, other: "KnowledgeGraph") -> Dict[str, int]:
        """Слить другой граф в текущий (аддитивно). Возвращает статистику."""

    def merge_from_prolog(
        self,
        text: str,
        generic_filter: Optional[Callable[[str], bool]] = None,
    ) -> Dict[str, int]:
        """from_prolog(text) → merge(...). Удобная обёртка."""
```

**Формат статистики:**

```python
{
    "added_nodes": 3, "skipped_nodes": 1,
    "added_edges": 2, "skipped_edges": 4,
    "added_attributes": 0, "skipped_attributes": 2,
}
```

**Правило.** `merge` не меняет `from_prolog`/`to_prolog` — контракт с PyAgentProlog сохранён. `merge` не требует `nl2prolog` — чистая операция над `KnowledgeGraph`.

### 11.3. Семантика (таблица)

| Аспект | Поведение |
|---|---|
| **Узлы** | Добавляются только отсутствующие. Тип и `props` существующих **не меняются** — текущий граф «выигрывает». |
| **Рёбра** | Дедуп по `(source, target, predicate)`. Дубликаты не создаются. |
| **Атрибуты** | Дедуп по `(entity, name, value)`. Если `(entity, name)` совпадает, но `value` отличается — это разные факты, оба останутся. |
| **Служебные слова** | Атомы, отброшенные `generic_filter` (`очень`, `наименование`), не добавятся и попадут в `skipped_*`. |
| **Ошибки по элементу** | Не прерывают merge — учитываются в `skipped_*`. Граф остаётся консистентным. |
| **`dlg_state`** | Не сбрасывается: merge — не замена, а пополнение. Pending-вопрос остаётся осмысленным. |
| **Порядок** | Существующие элементы остаются в своём порядке; новые добавляются в конец (dict/list в Python 3.7+ сохраняют порядок вставки). |

### 11.5. Хендлер `h_merge_file`

```python
def h_merge_file(g):
    """Объединить текущий граф с графом из файла (аддитивно)."""
    g = _safe(g)
    p = _pick_file(
        title="Объединить с графом (.pl)",
        filetypes=[("Prolog (*.pl)", "*.pl"), ("All files", "*.*")],
    )
    if not p:
        return _refresh(g) + (_status_html("Файл не выбран"),)
    try:
        with open(p, encoding="utf-8") as f:
            stats = g.merge_from_prolog(f.read())

        added = (stats["added_nodes"]
                 + stats["added_edges"]
                 + stats["added_attributes"])
        skipped = (stats["skipped_nodes"]
                   + stats["skipped_edges"]
                   + stats["skipped_attributes"])

        if added == 0 and skipped == 0:
            msg = f"ℹ️ Файл пуст: {p}"
        elif added == 0:
            msg = (f"ℹ️ Нечего добавлять: {p}\n"
                   f"  Всё уже есть в графе ({skipped} элементов пропущено).")
        else:
            msg = (
                f"✓ Объединено: {p}\n"
                f"  +{stats['added_nodes']} узлов, "
                f"+{stats['added_edges']} рёбер, "
                f"+{stats['added_attributes']} атрибутов\n"
                f"  пропущено (уже есть или невалидно): "
                f"{stats['skipped_nodes']} узлов, "
                f"{stats['skipped_edges']} рёбер, "
                f"{stats['skipped_attributes']} атрибутов"
            )
        return _refresh(g) + (_status_html(msg),)
    except Exception as e:
        return _refresh(g) + (_status_html(f"✗ Ошибка объединения: {e}"),)
```

### 11.10. Что **не** делать (дополнение к §8)

- ❌ **Полагать**, что `merge` перезаписывает существующие узлы — нет, аддитивно. Для перезаписи нужна отдельная политика (roadmap P3.1), её ещё нет.
- ❌ **Добавлять** `.then(lambda: None, [], [dlg_state])` к `merge_btn.click` — merge не заменяет граф.
- ❌ **Вызывать** `merge` без `try/except` вокруг `add_*` — одно битое ребро в файле не должно ломать весь merge.
- ❌ **Писать** статус `open`/`new`/`example`/`merge` в `import_status` — этот контрол удалён; только `project_status`.
- ❌ **Опускать** `generic_filter` при merge «для скорости» — служебные слова из файла загрязнят граф.
- ❌ **Считать**, что `added_* == 0` — это ошибка. Это валидный результат «нечего добавлять».

### 11.11. Что **всегда** (дополнение к §8)

- ✅ **Возвращать** `Dict[str, int]` из `merge` / `merge_from_prolog` — статистика нужна для `project_status` и тестов.
- ✅ **Проверять** `added == 0 and skipped == 0` отдельно от `added == 0` — пустой файл и «всё уже есть» — разные сообщения.
- ✅ **Синхронизировать** `_serialize_and_preview` после merge — Prolog source должен отражать новый граф.
- ✅ **Тестировать** merge на `identical.pl` и `noisy.pl` — два самых частых граничных случая.
