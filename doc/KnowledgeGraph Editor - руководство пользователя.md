## Что нового в v5.14

- **Слияние графов** — кнопка **«🔀 Объединить»** в проектной строке. Присоединяет граф из `.pl`-файла к текущему **аддитивно** (только добавление отсутствующего, без перезаписи существующего).
- **Статус проекта** вынесен в отдельный бокс под статистикой — сообщения о загрузке/создании/сохранении/слиянии видны сразу, без раскрытия аккордеона.
- **Диалог не сбрасывается при слиянии** — операция аддитивна, pending-вопрос остаётся осмысленным.
- **Счётчики `пропущено`** в статусе слияния — видно, сколько узлов/рёбер/атрибутов уже были в графе или отфильтрованы как служебные.

**Унаследовано от v5.13:** диалоговый режим в UI, транскрипт с `solutions`, PyVis freeze, порт 7861, possessive-фреймы, `_apply_facts_local`, расширенная диагностика.

## 1. Установка и запуск

### 1.1. Требования

| Компонент | Обязательно | Назначение |
|---|---|---|
| **Python** 3.10+ | ✅ | Runtime |
| **Gradio** 4.x / 5.x / 6.x | ✅ | UI |
| **PyVis** ≥ 0.3 | ⭐ сильно рекомендовано | Визуализация (без — заглушка) |
| **PyAgentProlog** (`prolog`) | ⭐ сильно рекомендовано | Запросы (без — панель запросов disabled) |
| **tkinter** | ⭐ | Нативные диалоги выбора файлов |
| **`nl2prolog`** | ⭕ опционально | NL-импорт + диалог (или собственный экстрактор) |
| **PyPDF2 / python-docx** | ⭕ | Чтение PDF/DOCX |

**Важно:** `nl2prolog` — **не зависимость**, а **экстрактор по умолчанию**. Без него редактор полноценно работает: открытие/сохранение/слияние `.pl`, редактирование узлов/рёбер/атрибутов, импорт Prolog-кода, запросы, визуализация. Не работает только NL-импорт и диалоговый режим.

### 1.2. Установка зависимостей

```bash
# Базовые (обязательно)
pip install gradio pyvis

# NL-импорт + диалог — вариант A: пакет nl2prolog (рекомендовано)
pip install "nl2prolog[ru,prolog]"

# NL-импорт — вариант B: только для своего конвертера — ничего не ставить
# (загрузите свой .py в UI, см. §4.4). Диалог при этом недоступен.

# PyAgentProlog (если нужны запросы)
pip install -e /путь/к/pyagentprolog

# Опционально: чтение PDF/DOCX
pip install PyPDF2 python-docx
```

### 1.3. Запуск

```bash
kg-editor
```

Откроется браузер на `http://127.0.0.1:7861`.

**CLI-параметры:**

```bash
kg-editor --host 0.0.0.0 --port 8080   # Доступ с других машин
kg-editor --share                      # Публичная ссылка gradio.live
kg-editor --no-browser                 # Не открывать браузер
```

**Python API:**

```python
from kg_editor import launch
launch(host="0.0.0.0", port=8080)
```

### 1.4. Проверка состояния после запуска

При старте `app.py` определяет четыре флага:
- `_T2P_OK` — работает ли `text_to_prolog` (встроенный или shim).
- `_NL2PROLOG_OK` — установлен ли пакет `nl2prolog`.
- `_AGENT_OK` — доступен ли `PyAgentProlog`.
- `_DIALOG_OK` — доступен ли `DialogTurn` из `nl2prolog`.

Результат виден в:
- **Баннере** в аккордеоне «📝 Импорт из НЛ».
- **Диагностике** (аккордеон «🔬 Диагностика» → «🔄 Показать»).
- **Вкладке «💬 Диалог»** — если `_DIALOG_OK == False`, показывается баннер вместо контролов.

## 2. Обзор интерфейса

Три колонки + модальные окна.

```
┌────────────────────┬──────────────────────┬────────────────────┐
│ 📁 Граф / Проект   │ 🧩 Редактор графа   │ 🖼️ Визуализация    │
│  📂 🔀 🆕 💾 📚    │  [Узлы][Рёбра]       │  (PyVis)           │
│  Статистика        │  [Атрибуты]          │                    │
│  Статус проекта    │  [🛡️ Отфильтровано]  │  🔎 Запросы       │
│                    │  [💬 Диалог]         │                    │
│  📝 Импорт из НЛ   │  [Prolog source]     │                    │
│  ⚙️ Конвертер      │                      │                    │
│  📥 Импорт Prolog  │                      │                    │
│  🔬 Диагностика    │                      │                    │
└────────────────────┴──────────────────────┴────────────────────┘
```

**Формат данных** (совместим с `nl2prolog._to_graph_program`):

```prolog
node(Id, Props, Type).           % узел: id, свойства, тип
edge(Source, Target, Predicate). % ребро
attribute(Entity, Name, Value).  % атрибут
```

При выполнении запросов поверх фактов автоматически добавляются правила:

```prolog
node(Id, Type) :- node(Id, _, Type).
edge(S, T) :- edge(S, T, _).
```

## 3. Работа с проектом

### 3.1. 📂 Открыть
Загрузить `.pl`-файл с диска. **Заменяет** текущий граф. **Сбрасывает активный диалог** (pending-вопрос теряет смысл для нового графа).

### 3.2. 🔀 Объединить — **новое в v5.14**

Загрузить `.pl`-файл и **присоединить** его содержимое к текущему графу. Текущий граф не заменяется — он **пополняется**.

**Где:** кнопка `🔀 Объединить` в проектной строке, между `📂 Открыть` и `🆕 Создать`.

**Что происходит:**

1. Открывается нативный диалог выбора `.pl`-файла.
2. Файл парсится в отдельный `KnowledgeGraph`.
3. Элементы **аддитивно** переносятся в текущий граф.
4. Результат виден в двух местах:
   - **Статус проекта** (бокс под статистикой) — подробный отчёт.
   - **Счётчики** (Узлов/Рёбер/Атрибутов) — обновляются автоматически.
5. Вкладка **«Prolog source»** пересобирается из объединённого графа.

**Семантика слияния** (политика «текущий граф выигрывает»):

| Элемент | Поведение |
|---|---|
| **Узлы** | Добавляются только отсутствующие. Если `apple` уже есть с типом `org`, а в файле — с типом `concept`, тип **не перезаписывается** (остаётся `org`). Свойства (`props`) существующих узлов тоже не меняются. |
| **Рёбра** | Дедуп по `(source, target, predicate)`. Совпавшие не дублируются. |
| **Атрибуты** | Дедуп по `(entity, name, value)`. Если `(entity, name)` совпадает, но `value` отличается — это разные факты, оба останутся. |
| **Служебные слова** | Атомы, отброшенные фильтром (`очень`, `наименование`, OCR-артефакты), не добавляются. Учитываются как `skipped`. |
| **Порядок** | Существующие элементы остаются на своих местах; новые — в конец (сохраняется порядок вставки). |

**Форматы сообщений в статусе:**

Успех с добавлением:
```
✓ Объединено: /path/to/file.pl
  +5 узлов, +7 рёбер, +2 атрибутов
  пропущено (уже есть или невалидно): 3 узлов, 1 рёбер, 0 атрибутов
```

Полное совпадение:
```
ℹ️ Нечего добавлять: /path/to/file.pl
  Всё уже есть в графе (10 элементов пропущено).
```

Пустой файл:
```
ℹ️ Файл пуст: /path/to/file.pl
```

Ошибка парсинга/слияния:
```
✗ Ошибка объединения: <текст исключения>
```
Граф при ошибке **не меняется** — операция атомарна для каждого элемента.

**Что НЕ происходит при слиянии:**

- Граф не заменяется — используйте `📂 Открыть`, если нужна именно замена.
- Тип и `props` существующих узлов не перезаписываются — это осознанная политика «текущий граф выигрывает».
- `dlg_state` **не сбрасывается** — это не замена, а пополнение. Если pending-вопрос был установлен, он остаётся валидным. Если хотите начать диалог заново — нажмите `🗑️` на вкладке «💬 Диалог».

**Типичные сценарии:**

| Задача | Действие |
|---|---|
| Собрать один граф из нескольких `.pl` | Открыть базовый → `🔀 Объединить` для каждого дополнительного |
| Добавить в текущий проект факты из другого источника | `🔀 Объединить` |
| Заменить граф целиком | `📂 Открыть` (не merge) |
| Проверить, что нового даёт файл | `🔀 Объединить` → посмотреть `+N` в статусе |

### 3.3. 🆕 Создать
Создать папку проекта с шаблоном `graph.pl`. **Заменяет** текущий граф. Сбрасывает диалог.

### 3.4. 💾 Сохранить
Сохранить в существующий файл или открыть «Сохранить как…».

### 3.5. 📚 Демо-граф
Загрузить `apple` / `iphone` / `spacex` / `elon_musk` с атрибутами и типами. **Заменяет** текущий граф. Сбрасывает диалог.

### 3.6. Статистика
Счётчики узлов / рёбер / атрибутов. Обновляются автоматически после каждого изменения (включая NL-импорт, слияние, запросы с мутациями и ходы диалога).

### 3.7. 📥 Импорт из Prolog
Вставьте Prolog-факты → **📥 Разобрать**. Текущий граф **заменяется**. Если нужен аддитивный режим — сохраните вставленный код в `.pl` и используйте `🔀 Объединить`.

### 3.8. 🔬 Диагностика

JSON-снимок текущего состояния (v5.14):

```json
{
  "summary": {"nodes": 42, "edges": 55, "attributes": 7},
  "pyagent": true,
  "t2p_ok": true,
  "nl2prolog_ok": true,
  "nl2prolog_version": "1.0.2",
  "t2p_custom": false,
  "dialog_ok": true,
  "dialog_active": false,
  "dialog_pending": false
}
```

| Поле | Значение |
|---|---|
| `pyagent` | доступен ли `prolog.agent.Agent` |
| `t2p_ok` | работает ли `text_to_prolog` (встроенный или shim) |
| `nl2prolog_ok` | установлен ли пакет `nl2prolog` |
| `nl2prolog_version` | версия пакета (или `null`) |
| `t2p_custom` | загружен ли пользовательский `.py` через UI |
| `dialog_ok` | работает ли `DialogTurn` (нужен `nl2prolog`) |
| `dialog_active` | инициализирован ли `DialogTurn` в текущей сессии |
| `dialog_pending` | есть ли ожидающий вопрос в диалоге |

## 4. NL-импорт: три режима

Аккордеон **«📝 Импорт из НЛ»** в Колонке 1. Внутри — **баннер статуса**, который сразу говорит, что работает.

### 4.1. Баннер — 5 возможных состояний

| Состояние | Что видно | Что делать |
|---|---|---|
| ✅ **`nl2prolog` установлен** | «✅ nl2prolog 1.0.2 — экстрактор по умолчанию» | Ничего. Работает из коробки. |
| ✅ **Встроенный `text_to_prolog`** | «✅ Встроенный text_to_prolog загружен (пакет nl2prolog не обнаружен)» | Работает через локальный модуль (нестандартная сборка). |
| ✅ **Пользовательский экстрактор** | «✅ Пользовательский экстрактор подключён» | Загружен `.py` через UI. |
| ⚠️ **Shim сломан** | «⚠️ nl2prolog X установлен, но shim text_to_prolog не загружается» | Проверьте установку пакета, либо загрузите свой `.py`. |
| ℹ️ **Экстрактора нет** | «ℹ️ Экстрактор NL не задан. NL-импорт недоступен» + инструкция | Загрузите свой `.py` (аккордеон «⚙️ Конвертер» уже раскрыт) или установите `pip install "nl2prolog[ru]"` |

### 4.2. Загрузка текста

- **Ручной ввод:** поле «Краткий текст».
- **Файл:** перетащите `.txt`, `.pdf`, `.docx` или `.fb2` в зону загрузки. Появится статус *«✅ Файл загружен (N символов)»* и кнопка **📝 Открыть текст**, которая открывает модальное окно для просмотра/редактирования полного текста. После правок — **✅ Применить** или **❌ Отмена**.

### 4.3. Две независимые кнопки

| Кнопка | Что делает | Граф | Поле «Запросы» |
|---|---|---|---|
| **📊 Факты** (primary) | `parse(text, strict=True, facts_from_questions=True)` | пополняется | не трогается |
| **❓ Запрос** | `parse(text, strict=True, facts_from_questions=False)` | не трогается | заполняется |

- **📊 Факты** — режим KB building: извлекает `node/3`, `edge/3`, `attribute/3` из **всех** предложений (включая вопросы).
- **❓ Запрос** — режим Q&A: превращает вопрос в Prolog-запрос, не загрязняя граф фактами из вопроса.
- **🗑️** — очистить введённый текст и состояние.

**Если экстрактор не задан** — обе кнопки возвращают подсказку:

```
ℹ️ Экстрактор NL не задан.
Редактор графа работает полностью — можно открывать/сохранять .pl,
редактировать узлы/рёбра/атрибуты, импортировать Prolog-код,
строить запросы.
Для NL-импорта нужно:
  → Загрузить свой .py-модуль с классом TextToProlog
  → Или установить встроенный: pip install "nl2prolog[ru]"
```

### 4.4. ⚙️ Пользовательский конвертер

Аккордеон **«⚙️ Пользовательский конвертер»** в NL-аккордеоне.

**Автоматически раскрыт**, если встроенный экстрактор не доступен (`_T2P_OK == False`).

Кнопки:
- **📂 Выбрать** — выбрать `.py`-файл.
- **✅ Загрузить** — импортировать модуль. Требуется класс `TextToProlog` с методом `parse()` **или** `convert()`.
- **↺ Встроенный** — вернуться к встроенному `text_to_prolog.py` (или к `nl2prolog`, если пакет установлен).

**При загрузке/сбросе конвертера активный диалог сбрасывается** — `dlg_state = None`. Это правильно: пользовательский экстрактор не даёт `DialogTurn`, старый диалог с новым экстрактором бессмыслен.

После успешной загрузки:
- Баннер меняется на «✅ Пользовательский экстрактор подключён».
- Кнопки **📊 Факты** / **❓ Запрос** используют ваш класс.
- Вкладка «💬 Диалог» показывает «⚠️ Диалоговый режим недоступен» (пользовательский `.py` не даёт `DialogTurn`).

**Требования к пользовательскому `.py`:**

```python
class TextToProlog:
    def __init__(self, **kwargs): ...
    def parse(self, text, **kwargs) -> tuple[str, str]: ...
    # или
    def convert(self, text, mode="graph", **kwargs) -> str: ...
```

Опционально — `filtered_atoms` атрибут, если хотите поддержать чекбокс «🛡️ Логировать отфильтрованное».

### 4.5. 🛡️ Логировать отфильтрованное

Чекбокс в NL-аккордеоне (по умолчанию **включён**).

При включении `parse(..., log_filtered=True)` заполняет `t2p.filtered_atoms` — список пар `(term_desc, reason)` всех термов, удалённых на этапах `_dedup` и `_postfilter_generic`.

Результат — на вкладке **🛡️ Отфильтровано** (Колонка 2).

**Типичные причины:**

| Причина | Что значит |
|---|---|
| `generic_adj: очень` | служебное прилагательное |
| `compound_ner_blacklisted: наименование_технопарка` | NER false-positive |
| `noise_atom: ст` | OCR-артефакт |
| `attr_label node: срок` | noun из `ATTR_LABEL_NOUNS` |
| `attr_label invert: наименование → должность` | переклассификация в `attribute(должность, наименование, true)` |
| `postfilter attr value noise: следующий` | Rel-прилагательное в значении атрибута |

При **выключенном** чекбоксе накладные расходы — нулевые.

## 5. Редактор графа

### 5.1. Вкладка «Узлы»

Таблица **id / type / degree** (degree = количество инцидентных рёбер).

- **Добавить:** `id`, `type` → **➕**.
- **Редактировать:** клик по строке → поля заполнятся → **💾**.
- **Удалить:** клик → **🗑️** (удаляются также все рёбра и атрибуты узла).

**Безопасное редактирование ID:**
- Если новый ID уже существует → «✗ Узел '…' уже существует», данные не теряются.
- Если новый ID невалиден → «✗ Ошибка переименования: …», граф не тронут.
- **Compound-ID разрешены:** `российская_федерация`, `northern_ireland`, `тихий_океан`.
- **Одиночные служебные слова** (`очень`, `этот`, `и`) отклоняются.

**Палитра типов:**

| Тип | Цвет |
|---|---|
| `concept` | 🔵 голубой |
| `person` | 🟢 зелёный |
| `org` / `organization` | 🟠 оранжевый |
| `place` / `loc` | 🟣 фиолетовый |
| `event` | 🔴 красный |
| `thing` | 💠 светло-голубой |
| `product` | 🟡 жёлто-оранжевый |
| `default` | ⚪ серый |

### 5.2. Вкладка «Рёбра»

Таблица **idx / source / predicate / target** (source и target — цветные чипы по типу узла).

- **Добавить:** `source`, `target`, `predicate` → **➕** (если source/target не в графе — создаются).
- **Редактировать:** клик → заполнится → **💾**.
- **Удалить:** клик → **🗑️**.

**Безопасное редактирование:** если source/target при редактировании невалиден — старая версия ребра не теряется, выводится ошибка.

### 5.3. Вкладка «Атрибуты»

Таблица **idx / entity / name / value**.

- **Добавить:** `entity`, `name`, `value` → **➕** (entity создаётся, если нет).
- **Удалить:** выбрать из выпадающего списка → **🗑️**.

### 5.4. Вкладка «🛡️ Отфильтровано»

Таблица **терм / атом** и **причина фильтрации** — что было удалено в процессе NL-импорта при включённом чекбоксе.

Интерактивный PyVis-граф, тёмная тема GitHub-dark.

- **Рёбра** — толщина 2.5, светло-серые `#8b949e`, при hover — голубые.
- **Hover** — всплывающие подсказки для узлов/рёбер.

| Действие | Результат |
|---|---|
| Колесо мыши | Зум |
| Drag фона | Панорама |
| Drag узла | Перетаскивание (узел **остаётся** на новом месте) |

## 7. Запросы

Движок — **PyAgentProlog** (`prolog.agent.Agent`). Запросы выполняются на «свежем» агенте — мутации (`assertz`, `retract`) не влияют на модель.

### 7.1. Синтаксис

Введите запрос (точку можно не ставить) → **▶ Запрос**. Лимит — 1000 решений.

### 7.2. Доступные предикаты

Автоматически добавляются удобные правила:

```prolog
node(Id, Type) :- node(Id, _, Type).
edge(S, T) :- edge(S, T, _).
```

Работают: `node/2`, `node/3`, `edge/2`, `edge/3`, `attribute/3`, `\+`, `=`, `\=`, `is`, `findall/3`, `member/2`, `append/3` и другие стандартные.

### 7.3. Примеры

| Запрос | Что вернёт |
|---|---|
| `node(apple, T).` | тип узла apple |
| `edge(X, Y, owns).` | кто чем владеет |
| `edge(A, B, _), \+ (A = B).` | все рёбра без петель |
| `findall(X, edge(apple, X, _), L).` | все цели рёбер apple |
| `node(A, person), node(B, org), edge(A, B, owns).` | персона → организация |

### 7.4. Результат

JSON-массив решений (`[{"X": "elon_musk", "Y": "spacex"}]`) или `{"result": true}` для ground-запросов.

### 7.5. Если PyAgentProlog не установлен

Панель запросов показывает «⚠️ PyAgentProlog не загружен». Редактор, визуализация, слияние и диалог продолжают работать (диалог выдаст «Нет решений» для каждого вопроса, т.к. `Agent` не вызывается).

## 8. Диалоговый режим

**Полноценный UI** — вкладка **«💬 Диалог»** в Колонке 2.

### 8.1. Что делает

- **Задаёт вопрос** → пытается найти ответ в графе через `Agent`.
- **Вводит утверждение** → извлекает факты и **добавляет их в граф** автоматически.
- **Уточняет** ответ через `✅ Да` / `❌ Нет` на pending-вопрос.
- Ведёт **транскрипт** всех ходов.

### 8.2. Контролы

| Элемент | Действие |
|---|---|
| **▶ Спросить** (primary) | NL-вопрос или утверждение → `DialogTurn.ask()` |
| **💬 Ответить** | NL-ответ на pending-вопрос → `DialogTurn.answer()` |
| **✅** | Ответ «да» на pending-вопрос |
| **❌** | Ответ «нет» на pending-вопрос |
| **🗑️** | Сброс диалога: очистить pending, сохранить историю |
| **📜 Транскрипт** | read-only поле с историей ходов |
| **⏳ Ожидающий вопрос** | Панель вверху — что ждёт ответа |

### 8.3. Сценарии

**Сценарий A — вопрос с ответом:**

1. Граф:
   ```prolog
   node('регулятор', [], org).
   edge('регулятор', 'лицензия', 'выдавать').
   ```
2. Ввести: `Кто выдает лицензию?` → **▶ Спросить**.
3. Результат:
   - `dlg_result`: `{"solutions": [{"X": "регулятор"}], "query": "edge(X, 'лицензия', 'выдавать')"}`
   - Статус: `✓ 1 решение(й)`
   - Транскрипт: `[02] system/answer ✓ 1 решение(й): X=регулятор`
   - **Pending очищен автоматически** (правильный ответ не требует уточнения).

**Сценарий B — вопрос без ответа:**

1. Граф пуст.
2. Ввести: `У пользователя есть лицензия?` → **▶ Спросить**.
3. Результат:
   - `dlg_result`: `{"result": None, "query": "edge('пользователь', 'лицензия', 'иметь')"}`
   - Статус: `Нет решений` + `💡 Решение не найдено. Нажмите ✅ Да / ❌ Нет`
   - Pending **установлен** — «⏳ Ожидающий вопрос: У пользователя есть лицензия?»

**Сценарий C — уточнение:**

1. Продолжение сценария B.
2. Нажать **✅** — `DialogTurn.answer("да")` → `convert_answer` генерирует `true_condition(edge('пользователь', 'лицензия', 'иметь'))`.
3. Факт `true_condition/1` **не добавляется** в граф (это не `node/edge/attribute`), но pending очищается.
4. Транскрипт: `[03] user/answer «да» facts (1): true_condition(...)`.

**Сценарий D — утверждение:**

1. Ввести: `Илон Маск владеет Tesla` → **▶ Спросить**.
2. NL-парсер возвращает `is_question: false` + `facts_extracted` с `node('илон_маск', _, person).` и `node('tesla', _, concept).`.
3. Факты **добавляются в граф** автоматически (см. §8.5).
4. Транскрипт: `[04] user/question «Илон Маск владеет Tesla» facts (2): …`

**Сценарий E — слияние во время диалога (v5.14):**

1. Нажать `🔀 Объединить` → присоединить файл с фактами.
2. **Диалог не сбрасывается** — pending-вопрос остаётся валидным.
3. Если в присоединённом файле появился ответ на pending-вопрос — нажмите `▶ Спросить` повторно (с тем же текстом или новым), `DialogTurn.ask` пересчитает решения на обновлённом графе.
4. Если нужен чистый диалог — `🗑️` на вкладке «💬 Диалог».

### 8.4. Транскрипт

Печатается из `DialogTurn.transcript()` (в `nl2prolog`). Формат:

```
[01] user/question
     «Кто выдает лицензию?»
     Q: edge(X, 'лицензия', 'выдавать')

[02] system/answer
     Q: edge(X, 'лицензия', 'выдавать')
     ✓ 1 решение(й):
         X=регулятор
```

Если в `DialogTurn` не установлена последняя версия транскрипта (без `solutions`) — обновите `nl2prolog` до v1.0.2+.

### 8.5. Применение фактов к графу

Утверждение → факты → граф делается через **`_apply_facts_local`** (в `app.py`):

- Строит `KnowledgeGraph.from_prolog(facts_src)`.
- Переносит узлы/рёбра/атрибуты в текущий граф.
- Возвращает `{nodes, edges, attributes}` или `{error}`.
- **Не использует** `nl2prolog.dialog.apply_facts_to_graph` — тот пытается импортировать `KnowledgeGraph` из своего пакета и падает с `'NoneType' object has no attribute 'from_prolog'`.

`true_condition/1`, `false_condition/1`, `user_condition/1` — не мапятся на `node/edge/attribute`, поэтому в граф не попадают (это ожидаемо).

### 8.6. Сброс диалога

- **🗑️** — `DialogTurn.reset()`: очищает `pending_query`, `pending_facts`, `pending_question_text`. История сохраняется.
- **Смена экстрактора** (📂 / ✅ / ↺ в «⚙️ Конвертер») — `dlg_state = None`.
- **Замена графа** (📂 Открыть / 🆕 Создать / 📚 Демо) — `dlg_state = None`.
- **Слияние** (🔀 Объединить) — `dlg_state` **не сбрасывается**: операция аддитивна, pending остаётся осмысленным.

### 8.7. Если `nl2prolog` не установлен

Вкладка «💬 Диалог» показывает **оранжевый баннер**:

> ⚠️ Диалоговый режим недоступен.
> Модуль dialog не загружается — нужен пакет nl2prolog.
> → Установите: `pip install "nl2prolog[ru]"`
> → Пользовательский .py-экстрактор для диалога недостаточен.

Контролы (▶, 💬, ✅, ❌, 🗑️) **скрыты**.

### 8.8. Fallback: вопрос не распознан

Если текст заканчивается на `?`, но `parse()` вернул пустой `query` — статус содержит:

```
⚠️ Вопрос не распознан парсером (NL-экстрактор вернул пустой запрос).
Извлечены только факты из текста.
💡 Попробуйте переформулировать вопрос.
```

Это сигнал обновить `nl2prolog` (v5.11.17+ распознаёт больше конструкций) или переформулировать.

## 9. Формат файла

```prolog
node(apple, [], org).
node(spacex, [], org).
node(российская_федерация, [], place).    % compound-ID без кавычек
edge(apple, iphone, releases).
edge(elon_musk, spacex, owns).
attribute(iphone, release_year, '2022').
```

- **ID / тип / предикат** — без кавычек, если валидный атом (`[a-z][A-Za-z0-9_]*`), иначе `'...'`.
- **Compound-ID** (`российская_федерация`) — валидный атом, идёт без кавычек.
- **Значения атрибутов** — всегда строки в `'...'`.

Файл для `🔀 Объединить` — тот же формат. Можно использовать вывод `💾 Сохранить` другого проекта.

## 10. Частые проблемы

### 10.1. Редактор не стартует: `ImportError: cannot import name 'DialogTurn'`

**Причина:** установлена старая версия `app.py` (до v5.12).

**Решение:** обновите `app.py` до v5.12+. Импорт `dialog.py` теперь полностью опционален.

### 10.2. Баннер: «ℹ️ Экстрактор NL не задан»

NL-импорт и диалог недоступны. Варианты:
- Установить: `pip install "nl2prolog[ru]"`.
- Загрузить свой `.py` в разделе «⚙️ Пользовательский конвертер» (он уже раскрыт). Диалог останется недоступен.

### 10.3. Баннер: «⚠️ nl2prolog X установлен, но shim не загружается»

**Причина:** пакет `nl2prolog` установлен, но `kg_editor.text_to_prolog` не может его импортировать.

**Решение:**
1. Проверить: `python -c "import nl2prolog; print(nl2prolog.__version__)"`.
2. Переустановить: `pip install --force-reinstall "nl2prolog[ru]"`.
3. Или загрузить свой `.py` через конвертер.

### 10.4. «✗ Узел '…' — служебное слово»

Скорее всего, вы пытаетесь добавить одиночное прилагательное / местоимение / предлог.

**Compound-ID разрешены** (`российская_федерация`, `тихий_океан`).

### 10.5. «Нет решений» в запросе

- Проверьте регистр: `apple` ≠ `Apple`.
- Строки `'2022'` и числа `2022` — разные.
- Проверьте предикат: `edge('регулятор', 'лицензия', 'выдает')` в KB, а запрос `edge(X, 'лицензия', 'выдавать')` — не совпадут (`выдает` ≠ `выдавать`). Используйте лемматизированную форму.

### 10.6. Диалог: «Нет решений» + ложное «Решение не найдено»

Если `solutions` содержит данные, а статус показывает «Решение не найдено» — обновите `app.py` до v5.13.0. В более ранних версиях `_dialog_hint_for_no_solution` ложно срабатывал (проверял `.get("result") is None`, что истинно и для отсутствующего ключа).

### 10.7. Диалог: `'NoneType' object has no attribute 'from_prolog'`

**Причина:** факты из утверждения пытались применить через `nl2prolog.dialog.apply_facts_to_graph`, который сломан.

**Решение:** обновите `app.py` до v5.13.0 — там `_apply_facts_local` использует `kg_editor.KnowledgeGraph`.

### 10.8. PyVis «дрожит» / «вращается»

**Причина:** физика не замораживается после stabilization (v5.12 и раньше).

**Решение:** обновите `graph_layout.py` до v5.13.0 — там `_PYVIS_FREEZE_JS` выключает physics по событию `stabilizationIterationsDone` и по таймауту 2.5 сек.

### 10.9. Двойные рамки у полей ввода

**Причина:** `.block` от темы Gradio + `border` из `.compact-tb input` — два контура.

**Решение:** обновите CSS до v5.12.1+ — `.compact-tb.block { border: none }` + единственный контур на `<input>`.

### 10.10. Пустая вкладка «🛡️ Отфильтровано»

- Включён ли чекбокс **🛡️ Логировать отфильтрованное**?
- Не нажимали ли импорт после его отключения?

### 10.11. Вопрос даёт `edge('кто', …)` вместо `edge(X, …)`

Обновите `nl2prolog` до **≥ 1.0.0**. Проверьте: диагностика должна показывать `nl2prolog_ok: true`, `nl2prolog_version: "1.0.x"`.

### 10.12. Не удалось прочитать PDF/DOCX

```bash
pip install PyPDF2 python-docx
```

### 10.13. `🔀 Объединить` → «ℹ️ Нечего добавлять»

**Причина:** все элементы из файла уже есть в графе (по политике дедупа). Это не ошибка — граф не изменился, потому что и так содержал всё нужное.

**Что проверить:** `skipped`-счётчики в статусе. Если они большие — значит, содержимое файла действительно дублирует текущий граф.

### 10.14. `🔀 Объединить` → тип узла не обновился

**Причина:** политика слияния — «текущий граф выигрывает». Существующие узлы не перезаписываются ни типом, ни `props`.

**Решение:** если нужно именно заменить тип — отредактируйте узел вручную на вкладке «Узлы» (клик → Type → 💾) или используйте `📂 Открыть`, если готовы заменить граф целиком.

### 10.15. `🔀 Объединить` → часть элементов пропала

**Причина:** атомы, отброшенные `generic_filter` (служебные слова, OCR-артефакты, NER false-positives), не добавляются при слиянии. Они учтены в `skipped`-счётчиках статуса.

**Что делать:**
- Если это ожидаемо (служебные слова) — ничего.
- Если это реальный термин, отброшенный фильтром, — добавьте узел вручную (вкладка «Узлы»).
- Если термин должен сохраняться всегда — настройте `generic_filter` в `graph_model.py` (см. §11.2).

### 10.16. После `🔀 Объединить` диалог ведёт себя странно

**Причина:** merge не сбрасывает `dlg_state`, но граф изменился — pending-вопрос мог стать неактуальным (например, ответ появился, или наоборот).

**Решение:**
- Нажмите `▶ Спросить` повторно — `DialogTurn.ask` пересчитает решения на обновлённом графе.
- Или `🗑️` на вкладке «💬 Диалог» для сброса pending и начала заново.

## 11. Архитектура

### 11.1. Файлы

| Файл | Роль | Версия |
|---|---|---|
| `app.py` | UI, handlers, тема, wiring, диалоговый режим, слияние | **v5.14** |
| `graph_model.py` | `KnowledgeGraph`, CRUD, (де)сериализация, `merge`/`merge_from_prolog` | **v5.13** |
| `graph_layout.py` | `render_pyvis()`, `render_svg()` (backup), freeze-JS | **v5.13** |
| `text_to_prolog.py` | **shim** → `nl2prolog` | shim |
| `dialog.py` | **shim** → `nl2prolog.dialog` + локальный `apply_facts_to_graph` | shim |
| **`nl2prolog`** *(отдельный пакет)* | NL-парсер + диалог | **v1.0.x** |
| `noise.py` | POS-noise (если без `nl2prolog`) | — |
| `metrics.py`, `runner.py` | Offline-оценка | — |

### 11.2. Точки расширения

**В `app.py`:**
- `_NODE_TYPE_COLORS` — палитра типов.
- `_CONVENIENCE_RULES` — правила для запросов.
- `_nl_package_status_html()` — баннер статуса экстрактора.
- `_dialog_unavailable_banner()` — баннер недоступности диалога.
- `_apply_facts_local()` — применение Prolog-фактов к графу.
- `h_merge_file()` — обработчик слияния (v5.14).

**В `graph_layout.py`:**
- `_TYPE_COLORS` — палитра PyVis.
- `_PYVIS_OPTIONS` — physics (стабилизация с заморозкой), edges (`continuous`), nodes.
- `_PYVIS_FREEZE_JS` — JS-хук, замораживающий physics после `stabilizationIterationsDone`.

**В `graph_model.py`:**
- `generic_filter=` — кастомный фильтр служебных слов.
- **`merge(other)`** — аддитивное слияние другого `KnowledgeGraph` в текущий (v5.13+).
- **`merge_from_prolog(text)`** — обёртка над `merge(from_prolog(text))` (v5.13+).

Политика `merge` (для справки): узлы — только отсутствующие, тип/props не перезаписываются; рёбра — дедуп по `(source, target, predicate)`; атрибуты — дедуп по `(entity, name, value)`. Возвращает статистику `{added_*, skipped_*}`.

**В `nl2prolog` (класс-атрибуты `TextToProlog`):**

| Список | Назначение |
|---|---|
| `NER_ORG_BLACKLIST` | абстрактные существительные → `concept` |
| `ATTR_LABEL_NOUNS` | лейблы атрибутов → `attribute/3` |
| `ATTR_ADJ_WHITELIST` | Rel-прил., которые **сохраняются** |
| `SHORT_PROTECTED` | короткие термины (не режутся) |
| `GENERIC_ADJ`, `OCR_ARTIFACTS` | fallback-фильтры |
| `SKIP_LEFTOVER_NOUNS`, `TEMPORAL_PLACE_LEMMAS` | служебные существительные |

**Расширение под домен:**

```python
from nl2prolog import TextToProlog
TextToProlog.ATTR_LABEL_NOUNS |= {'метрика', 'выборка', 'гипотеза'}
TextToProlog.NER_ORG_BLACKLIST |= {'регламент', 'постановление'}
TextToProlog.SHORT_PROTECTED |= {'оки', 'мвт', 'гкал'}
```

Файл `noise_ru.txt` (в каталоге `nl2prolog`) — расширение `ATTR_ADJ_WHITELIST` без правки кода.

### 11.3. Возможности `nl2prolog` v1.0.2

**Грамматические фреймы:**

| NL | Query |
|---|---|
| «Что такое X?» | `node(X, [], T)` |
| «Сколько X в Y?» | `attribute(Y, количество_X, V)` |
| «Когда \<participle\> X?» | `attribute(X, год_\<verbal_noun_gen\>, V)` |
| «Есть ли X у Y?» | `edge(Y, X, 'иметь')` |
| «У X есть Y?» | `edge(X, Y, 'иметь')` |
| «У кого есть X?» | `edge(X_var, X, 'иметь')` |
| «Какие X есть в Y?» | `edge(X, Y, 'находиться_в')` |
| «Кто владеет Tesla?» | `edge(X, 'tesla', 'владеть')` (position-first wh) |
| «Где находится X?» | `edge(X, Y, 'находиться_в')` (wh-locative) |

**Плюс:** URL-фильтр, Unicode-нормализация типографики (`’` → `'`, `—` → `-`), strict propagation, compound-merge UD (`технопарк_москва`, `флот_россия`).

**Если не устанавливать `nl2prolog`:** редактор всё равно работает, но NL-импорт требует пользовательский `.py`. Диалог недоступен.

## Что делать, если что-то не работает

**Быстрая диагностика:**

1. Откройте аккордеон **«🔬 Диагностика»** → **🔄 Показать**.
2. Посмотрите JSON:
   - `pyagent: false` → запросы недоступны (установите PyAgentProlog).
   - `t2p_ok: false` и `nl2prolog_ok: false` → NL-импорт недоступен.
   - `nl2prolog_ok: false` но `t2p_ok: true` → работает локальный shim.
   - `t2p_custom: true` → активен пользовательский экстрактор.
   - `dialog_ok: false` → диалог недоступен (установите `nl2prolog`).
   - `dialog_active: false` → диалог ещё не начат в этой сессии.
   - `dialog_pending: true` → есть ожидающий вопрос (нажмите ✅/❌).
3. Проверьте баннер в NL-аккордеоне — он показывает главное сообщение.
4. Проверьте баннер в вкладке «💬 Диалог» — если диалог недоступен, там оранжевое сообщение.
5. Для операций с проектом — смотрите бокс **«Статус проекта»** под статистикой: там сообщения о `📂 Открыть`, `🔀 Объединить`, `🆕 Создать`, `📚 Демо`, `💾 Сохранить`.

**Если не помогло** — пришлите:
- JSON из диагностики.
- Фрагмент консоли при старте `python -m kg_editor`.
- Версию: `python --version`, `pip show nl2prolog gradio pyvis`.
- Скриншот проблемной вкладки.
