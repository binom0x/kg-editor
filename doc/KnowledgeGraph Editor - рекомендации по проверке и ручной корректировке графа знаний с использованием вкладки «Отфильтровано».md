
**Назначение.** Практическое руководство по верификации NL-импорта: как читать лог фильтрации, что делать с каждой категорией причин, как отличить реальную ошибку парсера от «принятого loss» и как править граф вручную без потери данных.

**Аудитория.** Пользователь редактора, знакомый с основами Prolog и структурой графа (`node/3`, `edge/3`, `attribute/3`).

---

## 1. Зачем нужна вкладка «🛡️ Отфильтровано»

NL-парсер (`nl2prolog`) агрессивно удаляет шум: служебные слова, OCR-артефакты, NER false-positives, Rel-прилагательные. Это правильно для чистоты графа, но:

- часть удалений — **истинный шум**;
- часть — **принятый loss** (OCR-обрезки реальных слов, доменная избыточность);
- часть — **потенциально ценные факты**, удалённые по ошибке;
- часть — **системная настройка**, которую лучше исправить через класс-атрибуты и повторный импорт.

Вкладка «🛡️ Отфильтровано» — единственный способ увидеть, **что именно** удалено и **почему**. Без неё пользователь работает «слепо»: граф пополнился, но что потерялось — неизвестно.

---

## 2. Как включить и читать лог

1. Открыть **«📝 Импорт из НЛ»**.
2. Убедиться, что включён чекбокс **«🛡️ Логировать отфильтрованное»** (по умолчанию включён).
3. Загрузить текст вручную или файлом.
4. Нажать **«📊 Факты»**.
5. Переключиться на вкладку **«🛡️ Отфильтровано»** в Колонке 2.

Таблица содержит две колонки:

| терм / атом | причина фильтрации |
|---|---|
| `очень` | `generic_adj: очень` |
| `наименование_технопарка` | `compound_ner_blacklisted: наименование_технопарка` |
| `ст` | `noise_atom: ст` |
| `срок` | `attr_label node: срок` |
| `следующий` | `postfilter attr value noise: следующий` |

**Формат причины** — всегда `<категория>: <атом>`. Категория — ключевое слово до двоеточия; группируйте записи по нему.

**Важно:** лог показывает только то, что было удалено на этапах `_dedup`, `_postfilter_generic` и `_postfilter_attr_labels`. Он не показывает все ошибки парсера, неверные роли, пропущенные связи и NER-ошибки, которые не привели к фильтрации.

## 3. Каталог причин: что означает и что делать

### 3.1. `generic_adj: <слово>`

**Что:** служебное прилагательное / местоимение / предлог, удалённое на этапе `_dedup` или `_postfilter_generic`.

**Примеры:** `очень`, `этот`, `такой`, `следующий`, `настоящий`.

**Что делать:**
- Обычно оставить как есть — это истинный шум.
- Если слово — реальный термин в вашей предметной области (`общий`, `основной`, `капитальный`), добавьте его в `ATTR_ADJ_WHITELIST`:

```python
from nl2prolog import TextToProlog
TextToProlog.ATTR_ADJ_WHITELIST |= {'общий', 'основной', 'капитальный'}
```

Затем перезапустите импорт и проверьте, что слово исчезло из лога.

### 3.2. `noise_atom: <атом>`

**Что:** OCR-артефакт, слишком короткое слово (≤ 4 символов без `SHORT_PROTECTED`), pure number, документ-ID (`сд-4-3/21268`), URL-хвост.

**Примеры:** `ст`, `ых`, `пп`, `27`, `сд-4-3/21268`, `economicindex/.`.

**Что делать:**
- Обычно оставить — это шум.
- Если короткое слово — реальный термин (`оки`, `мвт`, `гкал`, `нму`), добавьте в `SHORT_PROTECTED`:

```python
TextToProlog.SHORT_PROTECTED |= {'оки', 'мвт', 'гкал', 'нму'}
```

- OCR-фрагмент реального слова (`управа`, `писание`, `законодатель`, `регионал`) — **принятый loss**, не восстанавливайте. Если в графе нет правильной сущности (`управляющая_компания`) — добавьте её вручную.

### 3.3. `compound_ner_blacklisted: <атом>`

**Что:** compound-атом, в составе которого есть лемма из `NER_ORG_BLACKLIST` — абстрактное существительное, ошибочно тегированное Natasha как ORG/LOC/PER.

**Примеры:** `наименование_технопарка`, `площадь_помещения`, `категория_земель`.

**Что делать:**
- Обычно оставить — это NER false-positives.
- Если слово — реальная сущность в вашем домене (`регламент`, `постановление`, `распоряжение`), удалите лемму из blacklist:

```python
TextToProlog.NER_ORG_BLACKLIST -= {'регламент', 'постановление'}
```

Перезапустите импорт. `регламент_42` должен появиться с типом `org`, а не `concept`.

### 3.4. `attr_label node: <существительное>`

**Что:** noun из `ATTR_LABEL_NOUNS` (`наименование`, `название`, `обозначение`, `площадь`, `категория`, `назначение`, `основание`, `перечень`, `срок`, `дата`, `номер`) попал в узел без типа. Это лейбл атрибута, а не сущность.

**Что делать:**
- Обычно оставить. `срок` не должен быть узлом; он должен быть ключом атрибута.
- Проверьте, что в графе есть правильная форма: `attribute(<entity>, 'срок', <value>)`. Если нет — добавьте атрибут вручную.
- Если слово в вашем домене — реальная сущность (`перечень` как документ), удалите его из `ATTR_LABEL_NOUNS`:

```python
TextToProlog.ATTR_LABEL_NOUNS -= {'перечень'}
```

### 3.5. `attr_label invert: <субъект> → <объект>`

**Что:** это **не фильтр, а аудит переклассификации**. Triplet `edge(<объект>, <субъект>, of)` инвертирован в `attribute(<объект>, <субъект>, 'true')`.

**Пример:** `edge('наименование', 'документ', of)` → `attribute('документ', 'наименование', 'true')`.

**Что делать:**
- Обычно ничего. Это правильная переклассификация.
- Проверьте вкладку «Атрибуты»: атрибут должен существовать.
- Если значение `'true'` бессмысленно, дополните его вручную.

### 3.6. `attr_label attr-name: <существительное>`

**Что:** noun из `ATTR_LABEL_NOUNS` попал в имя атрибута, например `attribute('срок', 'выдачи', 'true')`. Парсер дважды ошибся: сделал `срок` сущностью, затем попытался отфильтровать.

**Что делать:**
- Обычно оставить — это шум.
- Проверьте, что в графе есть правильный атрибут с тем же значением: `attribute(<правильный_entity>, 'срок', <value>)`.
- Если слово — реальная сущность, удалите из `ATTR_LABEL_NOUNS`.

### 3.7. `postfilter attr value noise: <прилагательное>`

**Что:** Rel-прилагательное в значении атрибута, например `attribute('документ', 'тип', 'следующий')`.

**Что делать:**
- Обычно оставить — значение атрибута должно быть конкретным.
- Если прилагательное — реальное значение (`федеральный` в специфическом контексте), можно добавить в `ATTR_ADJ_WHITELIST`, но осторожно: в НПА это почти всегда Rel-шум.

### 3.8. `postfilter triplet generic_adj: <слово>`

**Что:** служебное прилагательное в triplet-аргументе, удалённое после `_dedup`. Обычно дубликат `generic_adj`.

**Что делать:** как в §3.1.

### 3.9. `postfilter attr name generic_adj: <слово>`

**Что:** имя атрибута — служебное прилагательное.

**Что делать:** как в §3.6.

### 3.10. `postfilter generic_adj: <слово>`

**Что:** `fact/1` с служебным прилагательным, удалённый на этапе `_postfilter_generic`.

**Что делать:** как в §3.1.

## 4. Что **не** нужно восстанавливать: принятый loss

Если запись попадает в одну из категорий ниже — **не восстанавливайте**. Это приведёт к загрязнению графа.

### 4.1. OCR-обрезки реальных слов

**Примеры:** `управа`, `писание`, `законодатель`, `регионал`, `оговор`, `ответствие`, `техно`.

**Почему:** доменная избыточность компенсирует обрезки. В НПА «управляющая компания» встречается 100+ раз; один обрезок не теряет знания. Если в графе нет правильной сущности — добавьте её вручную, а обрезок оставьте отфильтрованным.

### 4.2. Rel-прилагательные в НПА

**Примеры:** `федеральный`, `промышленный`, `коммунальный`, `административный`, `следующий`, `настоящий`.

**Почему:** это шаблонные обороты. Если нужна сущность, она будет извлечена из полного словосочетания (`федеральный_закон_№_1863`), а не из одиночного прилагательного.

### 4.3. NER false-positives

**Примеры:** `наименование`, `площадь`, `категория`, `назначение`, `основание`, `перечень`, `требование`, `подпись`, `соглашение`, `заявление`, `положение`, `сторона`, `рекомендация`.

**Почему:** Natasha ошибочно тегирует их как ORG/LOC/PER в capitalized-позиции. В графе они должны быть атрибутами, не узлами.

### 4.4. Документ-идентификаторы

**Примеры:** `27`, `1863`, `сд-4-3/21268`.

**Почему:** это не сущности, а значения атрибутов (`attribute('документ', 'номер', '1863')`). Проверьте наличие такого атрибута; если нет — добавьте вручную.

### 4.5. Служебные прилагательные

**Примеры:** `очень`, `этот`, `такой`, `следующий`, `настоящий`.

**Почему:** истинный шум.

**Правило:** если в графе **нет** правильной сущности (`управляющая_компания`, `документ_1863`) — добавьте её вручную. Если она **есть** — обрезок (`управа`, `наименование`) не нужен.

## 5. Практический workflow проверки

### 5.1. Полный цикл (30–60 минут на документ 3–5 стр.)

**Шаг 1. Импорт с логом.**
1. Включить «🛡️ Логировать отфильтрованное».
2. Загрузить текст.
3. Нажать «📊 Факты».
4. Запомнить счётчики: `+N узлов, +M рёбер, +K атрибутов`.

**Шаг 2. Просмотр лога.**
1. Открыть «🛡️ Отфильтровано».
2. Просмотреть все записи, сгруппировать по префиксу причины.

**Шаг 3. Классификация записей.**

| Категория | Действие |
|---|---|
| Явный шум (`очень`, `этот`, `ст`, `27`) | Игнорировать |
| Принятый loss (OCR-обрезки, Rel-adj в НПА) | Игнорировать |
| Потенциально ценный факт | Восстановить вручную |
| Системная ошибка (много записей одного типа) | Настроить класс-атрибут и повторить импорт |

**Шаг 4. Верификация графа.**
1. «Узлы» — проверить топ-20 по degree; там не должно быть `очень`, `наименование`, `площадь`, `срок`.
2. «Рёбра» — проверить предикаты `of`, `являться`, `иметь`; они часто дают ложные связки.
3. «Атрибуты» — проверить `attribute(<entity>, 'срок', ...)`, `attribute(<entity>, 'номер', ...)`; entity должен быть реальной сущностью.
4. «Prolog source» → «🔄 Обновить из графа» — визуальный контроль.

**Шаг 5. Ручная корректировка.** См. §6.

**Шаг 6. Повторный импорт после настройки.**
1. «↺ Встроенный» в конвертере.
2. «📊 Факты» ещё раз.
3. Сравнить счётчики и лог. Целевые записи должны исчезнуть, остальной граф — не измениться.

**Шаг 7. Финальная проверка.**
1. «💾 Сохранить» → `.pl`.
2. Открыть `.pl` глазами.
3. Выполнить 2–3 запроса во вкладке «🔎 Запросы».

### 5.2. Быстрая проверка (5 минут)

1. «📊 Факты» с включённым логом.
2. «🛡️ Отфильтровано» — есть ли «очевидно ценные» записи?
3. «Узлы» — есть ли в топ-10 по degree мусор?
4. Если да — настроить класс-атрибуты или удалить вручную.
5. «💾 Сохранить».

## 6. Ручная корректировка: что и как

### 6.1. Восстановить ошибочно удалённый узел

1. Вкладка «Узлы» → `nid=оки`, `type=concept` → «➕».
2. Если термин повторяется — добавить в `SHORT_PROTECTED` и повторить импорт.

### 6.2. Восстановить ошибочно удалённое ребро

1. Вкладка «Рёбра» → `source`, `target`, `predicate` → «➕».
2. Если source/target не существуют — создадутся как `concept`.
3. Уточнить типы через вкладку «Узлы» → Type → «💾».

### 6.3. Исправить тип узла

1. Вкладка «Узлы» → клик по строке.
2. Ввести правильный тип: `person`, `org`, `place`, `event`, `product`, `concept`.
3. «💾».

### 6.4. Исправить ID / переименовать узел

1. Вкладка «Узлы» → клик по строке.
2. Ввести новый ID.
3. «💾».

Поведение:
- нового ID нет — узел переименован, рёбра и атрибуты перенаправлены;
- новый ID уже существует — «✗ Узел '…' уже существует», данные не теряются;
- новый ID невалиден (`очень`) — «✗ Ошибка переименования», граф не тронут;
- compound-ID разрешены: `российская_федерация`, `тихий_океан`.

### 6.5. Удалить мусорный узел

1. Вкладка «Узлы» → клик → «🗑️».
2. Удаляются также все рёбра и атрибуты узла.

Осторожно: если узел имеет 10+ рёбер — возможно, вы удаляете ценный хаб.

### 6.6. Исправить атрибут

В UI нет кнопки «Редактировать атрибут». Варианты:
1. Удалить неверный атрибут и добавить правильный: `entity`, `name`, `value` → «➕».
2. Через «Prolog source»: «🔄 Обновить из графа» → отредактировать `attribute(...)` → «📥 Применить».

### 6.7. Добавить отсутствующий атрибут

1. Вкладка «Атрибуты» → `entity=документ`, `name=срок`, `value=2022` → «➕».
2. Если `документ` нет в графе — создастся как `concept`; уточните тип.

### 6.8. Массовая корректировка через Prolog source

1. «Prolog source» → «🔄 Обновить из графа».
2. В аккордеоне «✏️ Редактировать» отредактировать текст.
3. «📥 Применить» — граф заменится целиком.

**Осторожно:** «Применить» заменяет граф полностью. Сначала «💾 Сохранить» текущий `.pl`.

## 7. Типичные сценарии

### 7.1. «В логе 50 записей `generic_adj: следующий`»

Диагноз: частое Rel-прилагательное в НПА. Действие: ничего, это истинный шум.

### 7.2. «В логе 20 записей `compound_ner_blacklisted: наименование_X`»

Диагноз: NER ошибочно тегирует `наименование_X` как ORG/LOC.
- Если `X` — реальный объект или лейбл атрибута — оставить.
- Если `X` — реальная сущность, которую нужно видеть, — удалить `наименование` из `NER_ORG_BLACKLIST`.

### 7.3. «В логе `noise_atom: 27`, `noise_atom: 1863`, `noise_atom: сд-4-3`»

Диагноз: документ-идентификаторы. Действие: ничего; проверить, что есть `attribute('документ', 'номер', '1863')`.

### 7.4. «В логе `attr_label node: срок`, но в графе нет `attribute(..., 'срок', ...)`»

Диагноз: парсер отфильтровал `срок`, но не создал атрибут. Действие: добавить атрибут вручную.

### 7.5. «В графе есть `node('следующий', [], concept)`, но в логе нет записи»

Диагноз: `_is_generic_adj` не распознал слово. Действие:
1. Удалить узел вручную.
2. Добавить `следующий` в `noise_ru.txt` или в `GENERIC_ADJ`:

```python
TextToProlog.GENERIC_ADJ |= {'следующий', 'настоящий'}
```

### 7.6. «Импорт дал `+0 узлов, +0 рёбер, +0 атрибутов`, в логе 100+ записей»

Диагноз: либо текст действительно не содержит сущностей, либо `strict=True` слишком агрессивен.
1. Проверить текст глазами.
2. Через Python API попробовать `strict=False`; в UI отдельного переключателя нет.
3. Если сущности только служебные — текст не подходит для KB building.

### 7.7. «`attr_label invert: наименование → должность`, но `должность` — не то»

Диагноз: переклассификация семантически неверна. Действие: удалить `должность` из `ATTR_LABEL_NOUNS` и повторить импорт.

### 7.8. «Импорт длится десятки секунд»

Диагноз: это не лог, а Natasha/spaCy на длинном тексте. `log_filtered=True` даёт <5% overhead. Для `reg_001` (3 стр.) 5–10 сек — норма; для `reg_1863` (65 стр.) 1–2 минуты — норма.

### 8.1. Минимальный (2 минуты)

- [ ] Открыть «🛡️ Отфильтровано» — есть ли записи, похожие на реальные термины?
- [ ] Открыть «Узлы» — есть ли в топ-10 по degree мусор?
- [ ] Открыть «Атрибуты» — все ли entity реальные сущности, не лейблы?
- [ ] «💾 Сохранить».

### 8.2. Расширенный (15–30 минут)

- [ ] Все записи лога классифицированы по §3–§4.
- [ ] Ценные термины восстановлены вручную.
- [ ] Системные ошибки исправлены через класс-атрибуты.
- [ ] Типы узлов проверены.
- [ ] Атрибуты `срок`, `номер`, `дата` имеют правильный entity.
- [ ] 2–3 запроса дают осмысленный результат.
- [ ] «💾 Сохранить».

### 8.3. Полный (для критичных документов)

- [ ] Расширенный чек-лист.
- [ ] Проход по всему `Prolog source` глазами.
- [ ] Сверка с исходным текстом: каждая сущность и связка есть в графе?
- [ ] Snapshot/assertions-тест, если есть.
- [ ] «💾 Сохранить» + коммит в git.

## 9. Профилактика: как уменьшить шум до импорта

1. **Чистка OCR перед импортом.** Постпроцессинг PDF уменьшает `noise_atom` на 30–50%.
2. **Удаление boilerplate.** Шапки, подписи, «УТВЕРЖДАЮ» — источник `generic_adj` и `noise_atom`; удаляйте в модалке «📝 Открыть текст».
3. **Доменные класс-атрибуты.** Настройте под домен:

```python
from nl2prolog import TextToProlog

# НПА
TextToProlog.NER_ORG_BLACKLIST |= {'регламент', 'постановление', 'распоряжение'}
TextToProlog.ATTR_LABEL_NOUNS |= {'редакция', 'приложение'}

# Наука
```

4. **Один домен — один корпус.** Смешивание НПА и научных статей даёт шум с обеих сторон.
5. **Проверка «на маленьком».** Сначала 1–2 абзаца, потом весь документ.

## 10. Ограничения подхода

1. **Лог показывает только атомы, отфильтрованные на этапах `_dedup`, `_postfilter_generic` и `_postfilter_attr_labels`.** Он не показывает все потери парсера: неверные роли, пропущенные связи, NER-ошибки без фильтрации, ошибки лемматизации, «принятые» обрезки, которые не попали в лог.
2. **Нет контекста предложения.** Видно только атом и причину; решение о восстановлении требует исходного текста.
3. **Причины эвристичны.** `generic_adj` может оказаться реальным термином; `noise_atom` — аббревиатурой; `compound_ner_blacklisted` — реальной сущностью.
4. **Нет кнопки «восстановить».** Только ручное добавление узла/ребра/атрибута или настройка класс-атрибутов и повторный импорт.
5. **Класс-атрибуты меняются в коде/сессии.** В UI нет редактора списков; после изменения нужен перезапуск/повторный импорт.
6. **Лог не заменяет snapshot/assertions/gold.** Для регресса нужны тесты, а не только визуальный просмотр.
7. **При выключенном чекбоксе лог пуст**, overhead нулевой.
8. **`attr_label invert` — не потеря, а аудит переклассификации.** Его нельзя «восстановить» как узел; нужно проверять итоговый `attribute/3`.
9. **Дедупликация по `(atom, reason)`.** Лог не показывает, сколько раз атом встретился в тексте.
10. **Пользовательский `.py`-экстрактор** поддерживает `filtered_atoms` только опционально; без этого вкладка будет пустой.
11. **Не все причины имеют отдельную категорию.** Ориентируйтесь на ключевое слово до `:`.
12. **UI не позволяет редактировать атрибут** — только удалить и добавить; массовые правки — через `Prolog source` с предварительным сохранением `.pl`.

**Главное правило:** если в графе нет правильной сущности — добавьте её вручную. Если она есть — обрезок или служебное слово из лога восстанавливать не нужно.
